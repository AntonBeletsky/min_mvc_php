## 1. Общие сведения

### 1.1. Назначение

`asguard01-php-mvc` — фреймворк минимального объёма для серверных веб-приложений на PHP по схеме Front Controller + MVC. Он принимает HTTP-запрос, по маршруту выбирает контроллер, создаёт его через DI-контейнер, получает ответ и безопасно отправляет его клиенту. Ядро не знает предметной области приложения: она живёт в каталоге `app/`.

Назначение проекта: эталонная реализация ядра, основа небольших HTML- и JSON-сервисов и платформа, к которой подключаются расширения (раздел 11) без правки ядра.

### 1.2. Цели и не-цели

**Цели.**

- **Ц-1.** Реализовать ровно десять функций ядра: единая точка входа, запрос и ответ, маршрутизация, диспетчеризация, конвейер middleware, DI-контейнер, конфигурация, шаблоны, доступ к данным, обработка ошибок (плюс журнал как часть обработки ошибок).
- **Ц-2.** Опираться на стандарты PHP-FIG, а не на собственные контракты: PSR-3, PSR-4, PSR-7, PSR-11, PSR-15, PSR-17.
- **Ц-3.** Быть безопасным по умолчанию: безопасные значения конфигурации, экранирование вывода, подготовленные запросы, нейтральные ответы об ошибках, заголовки безопасности.
- **Ц-4.** Не хранить состояние между запросами, чтобы ядро одинаково работало в классической модели «запрос — процесс» и в долгоживущих процессах (FrankenPHP worker, RoadRunner, Swoole).
- **Ц-5.** Быть полностью проверяемым: автоматические тесты, статический анализ на максимальном уровне, архитектурные тесты.
- **Ц-6.** Оставаться малым: ориентир — 1500–2500 строк исполняемого кода в `src/` без тестов и комментариев (оценка, уточняется по итогам этапа 3).

**Не-цели версии 1.0.** ORM и построитель запросов; сессии, аутентификация, авторизация, CSRF-защита, валидация ввода; консольные команды и миграции; кэш, события, очереди, почта, локализация; генерация кода, плагины, административная панель; шаблонизаторы уровня Twig/Blade; WebSocket и GraphQL. Для каждого пункта в разделе 11 описана точка расширения.

### 1.4. Сценарии использования

| Код | Сценарий | Ожидаемый результат |
| --- | --- | --- |
| UC-1 | `GET /` | HTML-страница главной, статус 200, `Content-Type: text/html; charset=UTF-8`, заголовки безопасности |
| UC-2 | Разработчик приложения добавляет маршрут `GET /posts/{id:\d+}` и контроллер | Параметр пути приходит в действие типизированным аргументом `int $id` |
| UC-3 | Запрос несуществующего пути; запрос известного пути неподходящим методом | 404; 405 с заголовком `Allow` |

| UC-5 | Клиент отправляет `Accept: application/json` и получает ошибку | Тело `application/problem+json` по RFC 9457 |
| UC-6 | Приложение работает в воркере FrankenPHP | Тысячи запросов подряд в одном процессе, данные одного запроса не видны другому |

### 1.5. Термины

| Термин | Значение |
| --- | --- |
| Front Controller | Единственный обработчик всех запросов сайта; общие задачи решаются в одном месте |
| Composition root | Место, где собирается граф объектов приложения: `public/index.php`, `public/worker.php`, `bootstrap.php`, `config/container.php` |
| Middleware | Звено конвейера PSR-15: принимает запрос и следующий обработчик, возвращает ответ |
| Конвейер (pipeline) | Цепочка middleware с конечным обработчиком; запрос идёт вперёд, ответ — назад |
| Конечный обработчик | Последнее звено конвейера — `Dispatcher` |
| Автоподстановка (autowiring) | Создание объекта по типам параметров конструктора без явного описания |
| Воркер (worker mode) | Процесс, который один раз загружает приложение и обрабатывает много запросов подряд |
| SAPI | Интерфейс запуска PHP: FPM, CLI, встроенный сервер, FrankenPHP |
| ZTS | Потокобезопасная сборка PHP; FrankenPHP использует её |
| Two Step View | Двухшаговое представление: сначала страница без оформления, затем общий макет |
| Problem Details | Формат ошибок HTTP API `application/problem+json` по RFC 9457 |
| `literal-string` | Тип PHPDoc: строка, написанная разработчиком или составленная только из таких строк; проверяется PHPStan |
| Last resort | Последняя линия обработки ошибок в `Kernel`: возвращает минимальный ответ 500 и не бросает исключений |

## 2. Технологический стек и среда выполнения

### 2.1. Версии PHP и политика поддержки

| Ветка | Состояние на 13.11.2026 | Роль в проекте |
| --- | --- | --- |
| 8.2 | Только исправления безопасности, до 31.12.2026 | Не поддерживается |
| 8.3 | Только исправления безопасности, до 31.12.2027 | **Минимальная версия** |
| 8.4 | Активная поддержка до 31.12.2026 | Поддерживается, входит в матрицу CI |
| 8.5 | Вышла 20.11.2025, активная поддержка до 31.12.2027 | Целевая версия, входит в матрицу CI |
| 8.6 | RC5 от 05.11.2026, финальный релиз запланирован на 19.11.2026 | Добавляется в матрицу CI после выхода; до первого патч-релиза допускается `continue-on-error` |

- **NFR-COMPAT-01.** Минимальная версия PHP — 8.3: `"php": "^8.3"` в `composer.json`. Ядро должно собираться и проходить тесты на всех ветках матрицы CI.
- **NFR-COMPAT-02.** Политика: ветка PHP поддерживается, пока она получает исправления безопасности. Минимальная версия повышается в минорном релизе фреймворка после окончания поддержки безопасности нижней ветки (для 8.3 — после 31.12.2027). Повышение отражается в `CHANGELOG.md`.
- **NFR-COMPAT-03.** PHP поддерживает ветку два года полностью и ещё два года — только исправления безопасности. Сроки для 8.4 и 8.5 после активной фазы следуют из этого правила; перед релизом их нужно сверить на php.net.
- **NFR-COMPAT-04.** Код `src/` не должен использовать возможности, появившиеся после минимальной версии 8.3 и потому недоступные на ней: свойства-хуки, асимметричную видимость, ленивые объекты, `#[\Deprecated]`, `new` без скобок (8.4); оператор `|>`, `clone` с заменой свойств, `#[\NoDiscard]`, расширение URI (8.5). Соблюдение проверяется сборкой и тестами на PHP 8.3 и конфигурацией `config.platform.php` в `composer.json` (приложение D).
- **NFR-COMPAT-05.** Код должен использовать возможности 8.1–8.3, где они упрощают проект: `declare(strict_types=1)`, перечисления, `readonly`-свойства и `readonly`-классы (8.2), `new` в инициализаторах, `never`, синтаксис first-class callable, `#[\SensitiveParameter]` (8.2), типизированные константы классов и `#[\Override]` (8.3), `json_validate()` (8.3).

### 2.7. Принципы проектирования

- **D-01. PSR first.** Где есть PSR, ядро использует его интерфейс и не вводит свой.
- **D-02. Явные зависимости.** Только внедрение через конструктор. Контейнер не передаётся в объекты. Исключения, перечисленные исчерпывающе: фабрики в `config/container.php` (получают представление контейнера на время вызова и не сохраняют его) и два инфраструктурных компонента ядра — `Kernel` (получает контейнер, чтобы собрать конвейер, и не хранит его) и `Dispatcher` (создаёт контроллеры). Контейнер не используется для получения собственных зависимостей этих классов.
- **D-03. Нет глобального состояния.** Нет `static`-свойств и `static`-переменных в функциях, одиночек, глобальных функций и `$GLOBALS`. Суперглобальные переменные читаются только в composition root.
- **D-04. Неизменяемость.** Value-объекты и сервисы без изменяемого состояния объявляются `final readonly`; объекты PSR-7 неизменяемы.
- **D-05. `final` по умолчанию.** Расширение — через интерфейсы и композицию.
- **D-06. Быстрый отказ при старте, безопасный отказ при работе.** Ошибки конфигурации обнаруживаются при сборке приложения; во время запроса клиент получает общий ответ без деталей.
- **D-07. Безопасность по умолчанию.** Незаданная переменная окружения даёт безопасное значение: `APP_ENV=prod`, `APP_DEBUG=false`.
- **D-08. Минимальность.** Функция входит в ядро, если без неё нельзя принять запрос и безопасно вернуть ответ либо её нельзя добавить снаружи без правки ядра.
- **D-09. Тонкие контроллеры.** Контроллер разбирает вход, вызывает сервис приложения и возвращает ответ; предметная логика живёт в `app/` и не наследует классы ядра.
- **D-10. Детерминизм.** Ядро не использует скрытые источники времени и случайности; время берётся в UTC.
- **D-11. Наблюдаемость.** Любая неожиданная ситуация попадает в структурированный журнал.
- **D-12. Документированные точки расширения.** Всё, что нужно подключать позже, перечислено в разделе 11.

## 3. Архитектура

### 3.1. Компоненты и слои

```text
Клиент ──HTTP──▶ веб-сервер (nginx / Apache / Caddy / FrankenPHP)
                        │
                        ▼
               public/index.php            Front Controller, composition root
                        │ ServerRequestInterface
                        ▼
  ┌──────────────────────  Kernel (RequestHandlerInterface)  ──────────────────────┐
  │  Pipeline (PSR-15)                                                              │
  │   SecurityHeaders ─▶ ErrorHandler ─▶ [прикладные middleware] ─▶ Dispatcher      │
  │                                                                   │             │
  │                                         Router ◀── Route[]        │ PSR-11      │
  │                                                                   ▼             │
  │                                          app/Controllers/* ──▶ View ──▶ resources/views
  │                                                  │                              │
  │                                                  ▼                              │
  │                                  сервисы приложения ──▶ Connection (PDO)        │
  └─────────────────────────────────────────────────────────────────────────────────┘
                        │ ResponseInterface
                        ▼
                ResponseEmitter ──▶ клиент

Сквозные компоненты: Config и Env · Container (PSR-11) · FileLogger (PSR-3) · HttpException
```

### 3.4. Сквозные соглашения

- **Стиль кода.** [PER Coding Style 3.1](https://www.php-fig.org/per/coding-style/); автоматическая проверка — `php-cs-fixer` с набором `@PER-CS3x0`. PER не требует `declare(strict_types=1)`, поэтому проект закрепляет это правило отдельно: каждый PHP-файл в `src/`, `app/`, `config/`, `public/`, `tests/` и `bootstrap.php` начинается с `<?php`, пустой строки и `declare(strict_types=1);`. Шаблоны в `resources/views/` следует начинать со строки `<?php declare(strict_types=1) ?>`.
- **Пространства имён.** `Asguard01\PhpMvc\` → `src/`, `App\` → `app/`, `Asguard01\PhpMvc\Tests\` → `tests/` (стандарт PSR-4). Один класс — один файл, имя файла равно имени класса.
- **Классы.** `final` по умолчанию; `readonly`, если у класса нет изменяемого состояния. Наследование допустимо только для исключений и обязательных базовых классов PSR (`Psr\Log\AbstractLogger`). Методы, реализующие интерфейс, помечаются `#[\Override]`.
- **Типы.** Все параметры, возвращаемые значения и свойства типизированы; `mixed` — только там, где иное невозможно (`ContainerInterface::get()`). Обобщённые типы, формы массивов и `literal-string` описываются в PHPDoc. PHPStan: уровень 10 (`max`), без baseline-файла.
- **Исключения.** Собственные исключения наследуют классы SPL. Клиентские ошибки выражаются `HttpException`. Пустые `catch`, оператор подавления `@`, `exit` и `die` запрещены; единственное исключение — перечисленные в FR-ERR-08 и FR-ERR-09 последние линии обороны, где перехват `Throwable` документирован.
- **Время.** Только UTC и `DateTimeImmutable`. Часовой пояс задаётся один раз в `bootstrap.php`.
- **Кодировка.** UTF-8 везде. Строки обрабатываются функциями `mb_*`, JSON — `json_encode`/`json_decode` с флагом `JSON_THROW_ON_ERROR`.
- **Журнал.** Только PSR-3, формат — JSON Lines (FR-LOG-02).
- **Отсутствие скрытого состояния.** Для каждого класса из `src/` и `app/` явно решено, изменяемый он или нет; изменяемое состояние допускается только как детерминированный кэш (рефлексия, скомпилированные маршруты) или как ресурс процесса (дескриптор журнала, соединение с БД).

### 3.5. Публичный API и совместимость

- **NFR-API-01.** Публичным API считаются публичные методы и конструкторы классов из `src/`, помеченные `@api` в PHPDoc, и интерфейсы, на которых они построены. Всё остальное — `@internal`.
- **NFR-API-02.** Версионирование по [SemVer 2.0.0](https://semver.org/lang/ru/): несовместимые изменения `@api` — только в мажорном выпуске; удаление возможности предваряется предупреждением `E_USER_DEPRECATED` и записью в `CHANGELOG.md` минимум за один минорный выпуск.
- **NFR-API-03.** Формат `CHANGELOG.md` — [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/).

## 4. Функциональные требования

Каждое требование проверяемо; соответствие требований тестам — в подразделе 8.2 и матрице трассировки (12.3). Для краткости «запрос» и «ответ» означают объекты PSR-7.

### 4.1. FR-ENTRY — единая точка входа и сборка приложения

- **FR-ENTRY-01.** Веб-сервер должен направлять в `public/index.php` все запросы, кроме запросов к существующим статическим файлам внутри `public/`.
- **FR-ENTRY-02.** Корнем веб-сервера должен быть каталог `public/`. Вне него не должно быть файлов, доступных по URL: `.env`, `vendor/`, `config/`, `storage/`, исходного кода.
- **FR-ENTRY-03.** `public/index.php` должен: получить `Kernel` из `bootstrap.php`; построить `ServerRequestInterface` из суперглобальных переменных; вызвать `Kernel::handle()`; передать ответ в `ResponseEmitter::emit()`. Файл не содержит маршрутов и логики приложения и не превышает 40 строк.
- **FR-ENTRY-04.** Исключение при сборке приложения или отправке ответа перехватывается в `public/index.php`: запись в `error_log()` (класс, сообщение, файл, строка, без аргументов трассировки) и, если заголовки ещё не отправлены, ответ 500 `text/plain` с телом `Internal Server Error`.
- **FR-ENTRY-05.** `bootstrap.php` должен возвращать готовый `Kernel` и выполнять только: подключение автозагрузчика Composer; `error_reporting(E_ALL)`; `display_errors=0`; часовой пояс UTC; внутреннюю кодировку UTF-8; установку обработчика ошибок PHP (FR-ERR-10); загрузку окружения и конфигурации; проверку инвариантов (FR-CFG-07); создание контейнера и ядра.
- **FR-ENTRY-06.** Классы загружаются только автозагрузчиком Composer (PSR-4). `require` и `include` для классов запрещены; допустимы только в `bootstrap.php`, `public/*.php`, при загрузке `config/*.php` и шаблонов.
- **FR-ENTRY-07.** В классическом режиме приложение собирается на каждый запрос, в воркере — один раз при старте процесса (P3).

### 4.2. FR-HTTP — запрос и ответ

- **FR-HTTP-01.** Ядро оперирует только интерфейсами PSR-7 (`ServerRequestInterface`, `ResponseInterface`, `StreamInterface`, `UriInterface`) и PSR-17. Конкретные классы `nyholm/*` допускаются только в composition root и тестах.
- **FR-HTTP-02.** Код `src/` и `app/` не читает суперглобальные переменные и не вызывает `header()`, `headers_sent()`, `http_response_code()`, `setcookie()`, `echo`, `print`, `exit`, `die`. Исключения: `ResponseEmitter` и composition root. Проверяется статическим анализом (запрет вызовов).
- **FR-HTTP-03.** `ResponseEmitter::emit()` отправляет ответ в таком порядке и по таким правилам:
  1. если `headers_sent()` истинно — `RuntimeException` с файлом и строкой, с которых начался вывод;
  2. статус-строка: `header(sprintf('HTTP/%s %d %s', …), true, $status)`;
  3. заголовки: первое значение каждого заголовка отправляется с заменой, остальные — без замены; значения `Set-Cookie` никогда не заменяются и не объединяются;
  4. `X-Powered-By` удаляется через `header_remove()`;
  5. если в ответе нет `Content-Length` и `Transfer-Encoding`, размер тела известен, а статус допускает тело — добавляется `Content-Length`;
  6. для статусов 1xx, 204, 205 и 304 тело не отправляется;
  7. тело читается потоково: `rewind()` для перематываемых потоков, блоки по 8192 байта (размер задаётся конструктором), без загрузки всего тела в память.
- **FR-HTTP-04.** Для запросов `HEAD` `Kernel` возвращает заголовки как для `GET`, но с пустым телом. Перед заменой тела `Kernel` фиксирует `Content-Length` по размеру исходного тела — если размер известен, заголовок ещё не задан, а статус допускает тело (иначе `ResponseEmitter` записал бы `Content-Length: 0`). Основание: по RFC 9110 сервер не отправляет содержимое в ответ на `HEAD`.
- **FR-HTTP-05.** Объекты запроса и ответа неизменяемы; middleware создаёт изменённые копии (`with*`) и не хранит запрос в свойствах.
- **FR-HTTP-06.** `HttpException` — единственный способ для кода приложения сообщить клиенту об ошибке 4xx/5xx. Исключение содержит статус 400–599, безопасное для клиента описание `detail` и дополнительные заголовки (например, `Allow`).

### 4.3. FR-ROUTE — маршрутизация

- **FR-ROUTE-01.** Синтаксис шаблона: путь начинается с `/`; статические сегменты; параметры `{name}` (по умолчанию один или несколько символов, кроме `/`) и `{name:регулярное_выражение}`. Имя параметра — `[A-Za-z_][A-Za-z0-9_]*`, уникальное в шаблоне. Необязательные сегменты не поддерживаются: регистрируются два маршрута.
- **FR-ROUTE-02.** Регулярное выражение ограничения не содержит захватывающих групп (используется `(?:…)`) и компилируется; проверка выполняется при построении `Router`.
- **FR-ROUTE-03.** Маршрут объявляется для одного или нескольких методов из набора `GET`, `HEAD`, `POST`, `PUT`, `PATCH`, `DELETE`, `OPTIONS`.
- **FR-ROUTE-04.** Приоритет: (1) точное совпадение статического пути; (2) динамические маршруты в порядке объявления. Выбирается первый маршрут, который подходит и по пути, и по методу; несовпадение метода не прерывает поиск.
- **FR-ROUTE-05.** Запрос `HEAD` обслуживается маршрутом `HEAD`, а при его отсутствии — маршрутом `GET`.
- **FR-ROUTE-06.** Если подходящего маршрута нет, но путь совпал с маршрутами для других методов, выбрасывается `HttpException` 405 с заголовком `Allow` (в ответе 405 сервер обязан его передавать — RFC 9110, подтверждено на MDN). Список методов без повторов, в алфавитном порядке; содержит `HEAD`, если есть `GET`, и всегда `OPTIONS`. Если путь не совпал ни с одним маршрутом — 404.
- **FR-ROUTE-07.** Нормализация пути: пустой путь заменяется на `/`; путь начинается с `/`; процентное декодирование выполняется один раз (`rawurldecode`) до сопоставления; в исходном и декодированном пути нет управляющих символов (0x00–0x1F, 0x7F); декодированный путь — корректный UTF-8. Нарушение — `HttpException` 400. Сегменты `.` и `..` не обрабатываются: их нормализует веб-сервер, а код, использующий параметры пути в файловой системе, сам проверяет результат.
- **FR-ROUTE-08.** Регистр символов в пути значим. Завершающий слэш значим: `/a` и `/a/` — разные пути; автоматических перенаправлений нет.
- **FR-ROUTE-09.** Ошибки определений выявляются при построении `Router`, а не при первом запросе: повтор пары «метод, шаблон», повтор имени маршрута, неверный шаблон, неверный метод — `InvalidArgumentException` с указанием маршрута.
- **FR-ROUTE-10.** Именованные маршруты: `Router::generate()` возвращает путь без схемы и хоста; значения параметров кодируются `rawurlencode` и проверяются по ограничению; недостающие или лишние параметры — `InvalidArgumentException`; параметры запроса формируются `http_build_query` в формате RFC 3986.
- **FR-ROUTE-11.** Ошибка PCRE (`preg_match` вернула `false`) — `RuntimeException` (ответ 500), а не молчаливый пропуск маршрута.

### 4.4. FR-DISP — диспетчеризация

- **FR-DISP-01.** `Dispatcher` — конечный обработчик конвейера. Он вызывает `Router::match()` и кладёт в запрос атрибуты `asguard01.route` (`Route`) и `asguard01.route_params` (`array<string, string>`).
- **FR-DISP-02.** Запрос `OPTIONS` без явного маршрута: если путь существует — ответ 204 с заголовком `Allow`, иначе 404. Явный маршрут `OPTIONS` обрабатывается как обычный.
- **FR-DISP-03.** Обработчик маршрута — пара `[класс, метод]` или имя класса с методом `__invoke`. Замыкания в маршрутах не поддерживаются: маршруты — чистые данные, пригодные для будущего кэша.
- **FR-DISP-04.** Контроллер создаётся контейнером. Контроллер — сервис без состояния; один экземпляр обслуживает все запросы процесса.
- **FR-DISP-05.** Аргументы действия разрешаются по порядку правил: (1) параметр типа `ServerRequestInterface` получает запрос; (2) параметр, чьё имя совпадает с параметром маршрута, получает значение, приведённое к объявленному типу (`string`, `int`, `float`, `bool`; без типа — строка; допустимы `?T` и значение по умолчанию); (3) иначе значение по умолчанию или `null` для nullable-типа; (4) иначе `LogicException`. Составные типы и классы, кроме запроса, не поддерживаются: сервисы внедряются только через конструктор.
- **FR-DISP-06.** Приведение параметра пути: `int` — `FILTER_VALIDATE_INT`; `float` — `FILTER_VALIDATE_FLOAT`; `bool` — только `1`, `0`, `true`, `false`. Невозможность приведения — `HttpException` 404, потому что путь не указывает на ресурс.
- **FR-DISP-07.** Действие обязано вернуть `ResponseInterface`; иное значение — `LogicException` (ответ 500, запись в журнале). Неявных преобразований строк, массивов и `null` нет.
- **FR-DISP-08.** План разрешения аргументов (рефлексия) кэшируется внутри `Dispatcher` по паре «класс, метод»; кэш детерминирован и не зависит от запроса.
- **FR-DISP-09.** Исключения контроллера `Dispatcher` не перехватывает: их обрабатывает `ErrorHandler`.

### 4.5. FR-MW — конвейер middleware

- **FR-MW-01.** Звенья реализуют `Psr\Http\Server\MiddlewareInterface`; конечный обработчик — `Psr\Http\Server\RequestHandlerInterface` (PSR-15).
- **FR-MW-02.** Порядок задаёт список в `config/middleware.php`: первый элемент выполняется первым на пути запроса и последним на пути ответа. Конечный обработчик `Dispatcher` подключается `Kernel` после последнего элемента.
- **FR-MW-03.** Звено может вернуть ответ, не вызывая следующий обработчик (короткое замыкание); PSR-15 это допускает.
- **FR-MW-04.** `Pipeline` неизменяем и реентерабелен: цепочка собирается один раз при создании, вызов `handle()` не меняет общее состояние.
- **FR-MW-05.** Middleware создаются контейнером при сборке `Kernel`. Элемент списка, не являющийся `MiddlewareInterface`, — `LogicException` при сборке.
- **FR-MW-06.** `ErrorHandler` присутствует в списке ровно один раз; отсутствие или повтор — `LogicException` при сборке. Он ставится сразу после звеньев, которые должны оформлять любой ответ, включая ответ об ошибке (`SecurityHeaders`); все прочие звенья идут после него. Звенья перед `ErrorHandler` не бросают исключений в штатной работе: исключения из них обрабатывает только last resort в `Kernel` (FR-ERR-09).
- **FR-MW-07.** Middleware не хранит данные запроса в свойствах и не использует `static`-состояние.

### 4.6. FR-DI — контейнер зависимостей

- **FR-DI-01.** `Container` реализует `Psr\Container\ContainerInterface`: `get(string $id): mixed` и `has(string $id): bool`. Неизвестный идентификатор — исключение, реализующее `NotFoundExceptionInterface`; прочие ошибки создания — `ContainerExceptionInterface`.
- **FR-DI-02.** Определения принимаются конструктором как `array<string, string|Closure|object>`: строка — алиас на другой идентификатор; `Closure(ContainerInterface): mixed` — фабрика; любой другой объект — готовый экземпляр. Метода добавления определений нет: после создания набор определений неизменяем.
- **FR-DI-03.** Автоподстановка для идентификатора-класса без определения использует рефлексию конструктора. Правила для параметра: (1) именованный тип класса или интерфейса, который контейнер может разрешить (`has()`), — `get(тип)`; ошибка разрешения этой зависимости пробрасывается и не подменяется значением по умолчанию; (2) тип, который разрешить нельзя, — значение по умолчанию, если оно есть (в том числе `null`), иначе `NotFoundException` или `ContainerException` с подсказкой добавить определение; (3) встроенный тип (`string`, `int`, `bool`, `array` и т. д.) — значение по умолчанию, иначе `ContainerException` с классом, именем параметра и подсказкой добавить фабрику; (4) union- и intersection-типы — значение по умолчанию, иначе `ContainerException`; (5) variadic — пустой набор. Интерфейс без определения — `NotFoundException`; абстрактный класс, перечисление и класс с закрытым конструктором — `ContainerException`.
- **FR-DI-04.** Все сервисы общие: повторный `get()` возвращает тот же экземпляр в пределах контейнера.
- **FR-DI-05.** Циклические зависимости обнаруживаются и приводят к `ContainerException`; в сообщении — цепочка идентификаторов (`A → B → A`), включая циклы через фабрики и алиасы.
- **FR-DI-06.** Цепочка разрешения передаётся параметром и не хранится в свойствах; фабрика получает не сам контейнер, а представление `ContainerInterface`, привязанное к текущей цепочке. Поэтому разрешение безопасно при вложенных и приостановленных вызовах (Fiber, корутины).
- **FR-DI-07.** Контейнер не регистрирует себя как сервис: `get(ContainerInterface::class)` — `NotFoundException`. Так контейнер не превращается в Service Locator, что соответствует рекомендации PSR-11 не передавать контейнер в объекты.
- **FR-DI-08.** `has($id)` возвращает `true`, если есть определение или существует инстанцируемый класс с таким именем. Это гарантирует, что `get()` не бросит `NotFoundExceptionInterface`, но не гарантирует отсутствия `ContainerExceptionInterface` (формулировка PSR-11).
- **FR-DI-09.** Сообщения исключений контейнера содержат идентификаторы и цепочку, но не значения параметров и не содержимое конфигурации.
- **FR-DI-10.** Результаты рефлексии конструкторов кэшируются внутри контейнера (детерминированный кэш).

### 4.7. FR-CFG — конфигурация и окружение

- **FR-CFG-01.** `Env::load($path)` читает файл `.env` (если он есть) и переменные процесса. Переменные процесса (`getenv()`) приоритетнее значений из файла. `$_SERVER` и `$_ENV` не используются: первый содержит данные запроса и CGI-окружение, второй пуст при `variables_order="GPCS"`.
- **FR-CFG-02.** Ядро не вызывает `putenv()` и не изменяет окружение процесса: так нет глобальных побочных эффектов и проблем с потокобезопасностью в ZTS-сборках.
- **FR-CFG-03.** Формат `.env`: UTF-8 (BOM игнорируется), окончания строк LF или CRLF. Пустые строки и строки, начинающиеся с `#`, пропускаются. Допустим префикс `export `. Строка имеет вид `ИМЯ=ЗНАЧЕНИЕ`, имя — `[A-Za-z_][A-Za-z0-9_]*`. Значение без кавычек обрезается по краям, комментарий начинается с ` #`. В одинарных кавычках значение буквальное; в двойных поддерживаются `\n`, `\r`, `\t`, `\"`, `\\`. Подстановка переменных (`${VAR}`) и многострочные значения не поддерживаются. Некорректная строка — `UnexpectedValueException` с именем файла и номером строки, без значения.
- **FR-CFG-04.** Файлы `config/*.php`, кроме `container.php`, `middleware.php` и `routes.php`, возвращают `callable(Env $env, string $basePath): array`; имя файла без расширения становится ключом верхнего уровня `Config`, файлы читаются в алфавитном порядке. Файлы `container.php`, `middleware.php`, `routes.php` — определения, их читает composition root: `container.php` возвращает `callable(Config $config, string $basePath): array` (определения для `Container`), `middleware.php` — `list<class-string>`, `routes.php` — `list<Route>`.
- **FR-CFG-05.** `Config` предоставляет `get()`, `has()` и типизированные `string()`, `int()`, `bool()`, `array()` с точечной нотацией ключей (`app.log.level`). Метод `get()` при отсутствии ключа возвращает переданное значение по умолчанию (`null`, если не передано). Типизированные методы при отсутствии ключа и без значения по умолчанию бросают `OutOfBoundsException`, при несоответствии типа — `UnexpectedValueException`; в сообщениях есть ключ, но нет значения.
- **FR-CFG-06.** `Config` и `Env` неизменяемы; `var_dump` и `print_r` не раскрывают значения (`__debugInfo()` возвращает только список ключей).
- **FR-CFG-07.** Инварианты проверяются при старте: `app.env` ∈ {`dev`, `test`, `prod`}; при `app.env = prod` значение `app.debug` обязано быть `false`. Нарушение — `LogicException` (быстрый отказ).
- **FR-CFG-08.** Значения по умолчанию безопасны: `APP_ENV=prod`, `APP_DEBUG=false`, `LOG_FILE=php://stderr`, `LOG_LEVEL=info`.
- **FR-CFG-09.** Конфигурация читается один раз при сборке приложения и не меняется во время работы.
- **FR-CFG-10.** Секреты не хранятся в репозитории: `.env` в `.gitignore`, `.env.example` содержит имена переменных и значения для локальной разработки без реальных секретов; в production значения приходят из переменных окружения или секретного хранилища платформы.

### 4.8. FR-VIEW — шаблоны

- **FR-VIEW-01.** Шаблоны — обычные PHP-файлы в `resources/views/`; имя файла равно имени шаблона плюс `.php`.
- **FR-VIEW-02.** `View::render()` возвращает строку; `View::response()` возвращает `ResponseInterface` с `Content-Type: text/html; charset=UTF-8`.
- **FR-VIEW-03.** Two Step View: если `layout` не `null` (по умолчанию `'layout'`), страница сначала отрисовывается в строку `$content`, затем макет отрисовывается с теми же данными и переменной `$content`.
- **FR-VIEW-04.** В шаблоне доступны замыкания: `$e` — текст HTML и значения атрибутов в кавычках; `$u` — компонент URL; `$j` — JSON внутри HTML; `$raw` — явная пометка заведомо безопасной разметки; `$include` — вложенный фрагмент (результат выводится сразу). `$e` использует `htmlspecialchars` с `ENT_QUOTES | ENT_SUBSTITUTE | ENT_HTML5` и кодировкой UTF-8, принимает `null`, скаляры и `Stringable`; массив или объект без `__toString` — `InvalidArgumentException` (вывода «Array» нет).
- **FR-VIEW-05.** Имена переменных данных — корректные идентификаторы, не совпадающие с зарезервированными (`e`, `u`, `j`, `raw`, `include`, `content`, `this`); нарушение — `InvalidArgumentException`.
- **FR-VIEW-06.** Имя шаблона соответствует `^[A-Za-z0-9_-]+(?:/[A-Za-z0-9_-]+)*$`; итоговый путь после `realpath` лежит внутри каталога шаблонов; отсутствующий шаблон — `InvalidArgumentException`. Имя шаблона никогда не строится из пользовательского ввода.
- **FR-VIEW-07.** Отрисовка использует буферизацию вывода; после исключения уровень буферов восстанавливается (`finally`).
- **FR-VIEW-08.** Вывод в шаблонах (`<?=`) идёт только через `$e(`, `$u(`, `$j(` или `$raw(`; автоматический тест проверяет все файлы `resources/views/**/*.php`.
- **FR-VIEW-09.** Шаблон не имеет доступа к контейнеру, соединению с БД и сервисам: вся информация приходит данными.
- **FR-VIEW-10.** Шаблоны страниц ошибок отрисовываются без макета и получают только данные `status` и `reason`.

### 4.9. FR-DATA — доступ к данным

- **FR-DATA-01.** `Connection` — тонкая обёртка над PDO без отображения на объекты. Базовых классов моделей и ORM в ядре нет: модели и репозитории пишутся в `app/`.
- **FR-DATA-02.** Соединение создаётся лениво, при первом обращении. Отсутствие параметров подключения выявляется при первом обращении понятным исключением, а не при старте приложения.
- **FR-DATA-03.** Параметры PDO по умолчанию: `ERRMODE_EXCEPTION`, `FETCH_ASSOC`, `EMULATE_PREPARES=false`, `STRINGIFY_FETCHES=false`; постоянные соединения выключены.
- **FR-DATA-04.** Запросы выполняются только как подготовленные, с привязкой параметров. Параметр SQL в PHPDoc имеет тип `literal-string`: PHPStan не пропустит строку, составленную с участием неконстантных данных. Имена таблиц, столбцов и направление сортировки параметризовать нельзя, поэтому вызывающий код выбирает их из жёсткого списка допустимых значений.
- **FR-DATA-05.** Типы привязки: `int` — `PARAM_INT`, `bool` — `PARAM_BOOL`, `null` — `PARAM_NULL`, `resource` — `PARAM_LOB`, `string` и `Stringable` — `PARAM_STR`; массив и прочие объекты — `InvalidArgumentException`. Допустимы именованные (`:name`) или позиционные (`?`) параметры, смешение запрещено.
- **FR-DATA-06.** Методы: `execute()`, `fetchAll()`, `fetchOne()`, `fetchValue()`, `lastInsertId()`, `transaction()`. `transaction(callable)` начинает транзакцию, подтверждает при успехе, откатывает при любом `Throwable` и пробрасывает исключение; вложенный вызов присоединяется к внешней транзакции без точек сохранения; исключение, вышедшее из вложенного вызова, помечает транзакцию «только откат», и внешний вызов откатывает её и бросает `LogicException`, даже если исключение было перехвачено. Публичных `begin` и `commit` нет, поэтому открытая транзакция не «утекает» в следующий запрос воркера.
- **FR-DATA-07.** При потере соединения (SQLSTATE класса `08`, коды MySQL 2006 и 2013) `Connection` отбрасывает дескриптор PDO и счётчик транзакций; следующее обращение создаёт новое соединение. Автоматического повтора уже начатой операции нет: её идемпотентность неизвестна.
- **FR-DATA-08.** Пароль не попадает в трассировки (`#[\SensitiveParameter]` на параметре конструктора, `zend.exception_ignore_args=On`) и в сообщения: ошибка подключения оборачивается в `RuntimeException('Unable to connect to the database: …')` без DSN и без `previous`.

### 4.10. FR-ERR — обработка ошибок

- **FR-ERR-01.** `ErrorHandler` — middleware, который перехватывает `Throwable` из нижележащих звеньев и конечного обработчика (размещение — FR-MW-06).
- **FR-ERR-02.** Классификация: `HttpException` — статус исключения (4xx: запись `info` без трассировки; 5xx: запись `error` с исключением); любые другие `Throwable` (включая `Error`, `ErrorException`, `PDOException`, `LogicException`) — статус 500 и запись `error` с исключением.
- **FR-ERR-03.** Формат ответа определяет заголовок `Accept` по алгоритму P10 (шаг 5): побеждает формат с большим весом `q`, при равных весах — с более конкретным диапазоном, при полном равенстве — HTML. Для JSON тело — `application/problem+json` по RFC 9457 (`type` = `about:blank`, `title` = фраза статуса, `status`, `detail` при непустом описании). `*/*`, `text/html` и отсутствие `Accept` дают HTML.
- **FR-ERR-04.** Тело ответа безопасно: для 5xx — только фраза статуса; для 4xx — фраза и `detail` из `HttpException`. В теле нет текста исключений, путей файлов, SQL, версий ПО и значений конфигурации. Для 5xx добавляется `Cache-Control: no-store`.
- **FR-ERR-05.** Режим отладки (`app.debug = true`, допустим только при `app.env ≠ prod`): HTML-страница с классом, сообщением, файлом, строкой и трассировкой (всё экранировано); для JSON — расширяющий член `debug`. Режим не включается неявно.
- **FR-ERR-06.** Для HTML-ответа используется шаблон `errors/<статус>`; если его нет или отрисовка завершилась исключением — встроенная минимальная HTML-страница с экранированной фразой статуса.
- **FR-ERR-07.** Перед формированием ответа закрываются буферы вывода, открытые во время запроса (уровень запоминается при входе в звено); отброшенный вывод фиксируется записью `warning`.
- **FR-ERR-08.** Двойной сбой: ошибка при формировании ответа об ошибке (шаблон, журнал) не выходит за пределы `ErrorHandler`; возвращается ответ 500 `text/plain` с телом `Internal Server Error`, запись выполняется через `error_log()`.
- **FR-ERR-09.** `Kernel::handle()` не бросает исключений: исключение, дошедшее до него (из звеньев перед `ErrorHandler` или из самого `ErrorHandler`), порождает last resort — ответ 500 `text/plain` с заголовками `Cache-Control: no-store` и `X-Content-Type-Options: nosniff`, запись через `error_log()`. Исключение из гарантии: отказ самих фабрик PSR-17 (невозможно создать даже ответ) — аномалия среды, её обрабатывает composition root (FR-ENTRY-04).
- **FR-ERR-10.** Ошибки PHP преобразуются в `ErrorException` обработчиком из `bootstrap.php` с учётом `error_reporting()`; предупреждения об устаревании (`E_DEPRECATED`, `E_USER_DEPRECATED`) пишутся через `error_log()` и не прерывают запрос.
- **FR-ERR-11.** Заголовки из `HttpException` (например, `Allow`) переносятся в ответ.
- **FR-ERR-12.** Если у запроса есть атрибут `request_id`, его значение добавляется в контекст каждой записи журнала `ErrorHandler` (точка расширения для идентификатора запроса и трассировки).

### 4.11. FR-LOG — журнал

- **FR-LOG-01.** `FileLogger` реализует `Psr\Log\LoggerInterface` через `AbstractLogger`: восемь уровней RFC 5424; `log()` с неизвестным уровнем — `Psr\Log\InvalidArgumentException` (требование PSR-3).
- **FR-LOG-02.** Формат — JSON Lines: одна запись — одна строка JSON в UTF-8, оканчивающаяся `\n`. Поля: `time` (UTC, RFC 3339 с микросекундами и суффиксом `Z`), `level`, `message`, `context`. Перевод строки внутри значений экранирует сам JSON, что нейтрализует внедрение поддельных строк в журнал.
- **FR-LOG-03.** Записи ниже порога (`LOG_LEVEL`) отбрасываются.
- **FR-LOG-04.** Плейсхолдеры `{ключ}` в сообщении заменяются значениями контекста (только скаляры и `Stringable`), как разрешает PSR-3.
- **FR-LOG-05.** Исключение из ключа `exception` сериализуется в объект с ключами `class`, `message`, `code`, `file`, `line`, `trace` и `previous`: трассировка — не более 30 кадров вида `{file, line, function}`, где `function` — `класс::функция`, без аргументов; `previous` — вложенный объект того же вида. Значение ключа сначала проверяется на принадлежность к `Throwable`: по PSR-3 в этом ключе может лежать что угодно.
- **FR-LOG-06.** Редактирование: значения по ключам, содержащим (без учёта регистра) `password`, `passwd`, `secret`, `token`, `authorization`, `cookie`, `api_key`, `apikey`, `dsn`, `credential`, заменяются на `[REDACTED]` на любой глубине вложенности.
- **FR-LOG-07.** Ограничения: глубина контекста — 5, элементов массива — 50, длина строки — 2000 символов, запись целиком — 16384 байта (усечение с пометкой). Ресурсы, замыкания и объекты без `Stringable` заменяются описанием типа.
- **FR-LOG-08.** Логгер никогда не бросает исключений и не вызывает ошибки, предупреждения или уведомления PHP, что бы ни лежало в контексте (требование PSR-3); при сбое записи выполняется один резервный вызов `error_log()`.
- **FR-LOG-09.** Назначение — `php://stderr`, `php://stdout` или путь к файлу; по умолчанию `php://stderr`; относительный путь `config/app.php` разрешает от корня проекта. Логи пишутся в поток событий, а маршрутизацию и хранение берёт на себя среда выполнения ([Twelve-Factor, фактор «Logs»](https://12factor.net/logs)). Ротация — внешняя.
- **FR-LOG-10.** Запись строки выполняется одним вызовом: для файла — `file_put_contents(…, FILE_APPEND | LOCK_EX)`, для потока — одним `fwrite`.

### 4.12. FR-SEC — заголовки безопасности

- **FR-SEC-01.** `SecurityHeaders` добавляет к каждому ответу заголовки из приложения B, если обработчик их ещё не задал.
- **FR-SEC-02.** Значения настраиваются в `config/app.php` (ключ `security_headers`); пустое значение отключает заголовок.
- **FR-SEC-03.** `Strict-Transport-Security` отправляется только если параметр сервера `HTTPS` (из `ServerRequestInterface::getServerParams()`) задан и не равен `off` (без учёта регистра). Схема из URI запроса не используется: `nyholm/psr7-server` 1.1.0 при создании URI берёт схему в том числе из заголовка `X-Forwarded-Proto`, который присылает клиент (проверено по исходному коду библиотеки). При терминации TLS на прокси веб-сервер, которому доверяют, обязан передать PHP `HTTPS=on`. Директива `preload` по умолчанию не добавляется.
- **FR-SEC-04.** Политика CSP по умолчанию запрещает встроенные скрипты и стили; режим report-only включается заменой имени заголовка на `Content-Security-Policy-Report-Only` в настройке `security_headers`.
- **FR-SEC-05.** Звено не бросает исключений в штатной работе: оно расположено перед `ErrorHandler` (FR-MW-06).

## 5. Процессы работы фреймворка

Раздел описывает динамику: что происходит, в каком порядке и с какими результатами. У каждого процесса есть код `P1`–`P12`, шаги, граничные случаи и ссылки на требования раздела 4. Псевдокод поясняет логику и не диктует реализацию; обязательны наблюдаемые результаты — статусы, заголовки, исключения, записи журнала и состояние объектов.

### 5.0. Обзор жизненного цикла

```text
запрос ─▶ index.php ─▶ Kernel::handle ─▶ SecurityHeaders ─▶ ErrorHandler ─▶ [middleware] ─▶ Dispatcher
                                                                                                │
                                                     P5  Router::match ◀────────────────────────┤
                                                     P7  Container::get(контроллер) ◀───────────┤
                                                     P6  вызов действия ─▶ контроллер ─▶ P9 Connection, P8 View
                                                                                                │
ответ ◀─ ResponseEmitter (P12) ◀─ Kernel (HEAD, last resort) ◀─ SecurityHeaders ◀─ ErrorHandler ◀┘
```

| Код | Процесс | Когда выполняется | Главные участники |
| --- | --- | --- | --- |
| P1 | Старт приложения (сборка) | Один раз на процесс (воркер) или на каждый запрос (классический режим) | `bootstrap.php`, `Env`, `Config`, `Container`, `Kernel` |
| P2 | Запрос в классическом режиме | На каждый запрос | `public/index.php`, `Kernel`, `ResponseEmitter` |
| P3 | Цикл воркера | Один раз на процесс; внутри — цикл по запросам | `public/worker.php`, FrankenPHP |
| P4 | Прохождение конвейера | На каждый запрос | `Pipeline`, middleware |
| P5 | Маршрутизация | На каждый запрос; компиляция — при старте | `Router`, `Route` |
| P6 | Диспетчеризация | На каждый запрос | `Dispatcher` |
| P7 | Разрешение зависимостей | При первом обращении к сервису | `Container` |
| P8 | Отрисовка шаблона | По обращению контроллера или `ErrorHandler` | `View` |
| P9 | Доступ к данным | По обращению приложения | `Connection` |
| P10 | Обработка ошибок | При исключении | `ErrorHandler`, `Kernel` |
| P11 | Журналирование | При каждой записи | `FileLogger` |
| P12 | Отправка ответа | На каждый запрос | `ResponseEmitter` |

### 5.1. P1 — Старт приложения

| Параметр | Значение |
| --- | --- |
| Вход | Корень проекта (`__DIR__` файла `bootstrap.php`), переменные процесса, файл `.env`, файлы `config/*.php` |
| Результат | Готовый объект `Kernel`; все ошибки определений выявлены |
| Требования | FR-ENTRY-05..07, FR-CFG-01..09, FR-DI-02, FR-MW-05, FR-MW-06, FR-ROUTE-09 |

**Шаги.**

```text
1.  basePath = каталог bootstrap.php
2.  require vendor/autoload.php
3.  error_reporting(E_ALL); display_errors = 0; часовой пояс UTC; mb_internal_encoding('UTF-8')
4.  set_error_handler(предупреждения → ErrorException; deprecated → error_log, без прерывания)
5.  env    = Env::load(basePath/.env)                 # переменные процесса приоритетнее файла
6.  config = Config::load(basePath/config, env, basePath)
7.  проверить инварианты: app.env ∈ {dev, test, prod}; prod ⇒ debug = false   → иначе LogicException
8.  definitions = (require config/container.php)(config, basePath)
9.  container   = new Container(definitions)
10. middleware  = require config/middleware.php         # list<class-string>
11. kernel      = new Kernel(container, middleware, ResponseFactory, StreamFactory)
        11.1  проверить список: каждый элемент — MiddlewareInterface; ErrorHandler ровно один раз
        11.2  router     = container.get(Router::class)          # здесь же компилируются маршруты
        11.3  dispatcher = new Dispatcher(router, container, ResponseFactory)
        11.4  звенья     = container.get(класс) для каждого элемента списка, по порядку
        11.5  pipeline   = new Pipeline(звенья, dispatcher)
12. вернуть kernel
```

**Граф объектов после старта.**

```text
Kernel
 ├─ Pipeline
 │   ├─ SecurityHeaders ········ Config: app.security_headers
 │   ├─ ErrorHandler ··········· LoggerInterface (FileLogger) · View · фабрики PSR-17 · флаг debug
 │   ├─ [прикладные middleware]
 │   └─ Dispatcher ············· Router (Route[]) · ContainerInterface · ResponseFactory
 ├─ ResponseFactoryInterface ···· Psr17Factory (nyholm/psr7)
 └─ StreamFactoryInterface ······ Psr17Factory (nyholm/psr7)

Создаются по первому обращению: контроллеры (P7), Connection (соединение — при первом запросе SQL).
```

**Ошибки и граничные случаи.**

| Ситуация | Исключение | Результат |
| --- | --- | --- |
| Нет `vendor/autoload.php` | Фатальная ошибка PHP (до перехвата) | Запись в журнал PHP; ответ 500 формирует веб-сервер |
| Некорректная строка `.env` | `UnexpectedValueException` (имя файла и номер строки, без значения) | `index.php`: запись в журнал, 500 `text/plain` |
| Нарушен инвариант (`prod` и `debug`) | `LogicException` | То же |
| Повтор маршрута, неверный шаблон | `InvalidArgumentException` | То же |
| В списке middleware нет `ErrorHandler`, он повторяется или элемент не `MiddlewareInterface` | `LogicException` | То же |
| Неразрешимая зависимость | `ContainerException` / `NotFoundException` | То же |

**Свойства.** Сборка не выполняет сетевых и файловых обращений, кроме чтения `.env`, `config/*.php` и подключаемых классов; соединение с БД не открывается (FR-DATA-02); файл журнала открывается при первой записи. В воркере ошибка старта завершает скрипт воркера; политику перезапуска задаёт FrankenPHP (поведение следует сверить с документацией на дату внедрения).

### 5.2. P2 — Запрос в классическом режиме

| Параметр | Значение |
| --- | --- |
| Среды | nginx + PHP-FPM, Apache, встроенный сервер, FrankenPHP без воркера |
| Вход | HTTP-запрос |
| Результат | HTTP-ответ; по окончании запроса PHP освобождает всё состояние |
| Требования | FR-ENTRY-01..04, FR-HTTP-01..04 |

```text
1. Веб-сервер: файл существует в public/ → отдать его; иначе → public/index.php (FR-ENTRY-01).
2. index.php: kernel = require bootstrap.php                 # P1
3. request = ServerRequestCreator::fromGlobals()              # суперглобальные читаются только здесь
4. response = kernel.handle(request)                          # P4; не бросает исключений (FR-ERR-09)
5. ResponseEmitter::emit(response)                            # P12
6. Конец запроса: объекты уничтожены, соединения закрыты, память возвращена.
```

Любое исключение шагов 2, 3, 5 перехватывает `index.php` (FR-ENTRY-04): `error_log()` с классом, сообщением, файлом и строкой; если заголовки ещё не отправлены — ответ 500 `text/plain` `Internal Server Error`; если отправлены — только запись в журнал, дописывать тело нельзя.

### 5.3. P3 — Цикл воркера (FrankenPHP worker mode)

| Параметр | Значение |
| --- | --- |
| Вход | Сигналы FrankenPHP: очередной запрос; переменная `MAX_REQUESTS` |
| Результат | Тысячи запросов в одном процессе без утечек данных между ними |
| Требования | FR-ENTRY-07, D-03, Ц-4; раздел 9 (`public/worker.php`); тесты 8.2 (T-WK-*) |

```text
запуск воркера (один раз)                      цикл (на каждый запрос)
─────────────────────────                      ───────────────────────────────────────
ignore_user_abort(true)                        keepRunning = frankenphp_handle_request(handler)
kernel  = require bootstrap.php   # P1             └─ handler:
фабрики и эмиттер создаются один раз                    уровень буферов запомнить
maxRequests = MAX_REQUESTS (0 = без предела)            request  = fromGlobals()        # суперглобальные уже сброшены
                                                        response = kernel.handle()      # P4
                                                        emit(response)                  # P12
                                                        иначе при Throwable: журнал + 500, если заголовки не отправлены
                                                        лишние буферы вывода закрыть, записать warning
                                               gc_collect_cycles()
                                               выход, если keepRunning = false или счётчик достиг maxRequests
```

**Нормативные правила воркера.**

- **WK-1.** `Kernel`, фабрики PSR-17 и `ResponseEmitter` создаются один раз при старте; `ServerRequest` создаётся на каждый запрос.
- **WK-2.** Исключение одного запроса не завершает воркер: обработчик перехватывает `Throwable`, пишет в журнал и, если заголовки не отправлены, отвечает 500 (в штатной работе исключения не доходят сюда, потому что `Kernel::handle()` их не бросает).
- **WK-3.** После каждого запроса вызывается `gc_collect_cycles()`, чтобы сборщик мусора не срабатывал посреди формирования следующей страницы (приём из документации FrankenPHP).
- **WK-4.** Перед обработкой запоминается уровень буферов вывода; после — лишние буферы закрываются, а факт фиксируется записью `warning`.
- **WK-5.** Значение `MAX_REQUESTS` ограничивает время жизни процесса и страхует от медленных утечек памяти; значение подбирается по метрикам, стартовый ориентир — 500–1000 (не проверено; подлежит замеру на этапе 5).
- **WK-6.** Между запросами живёт только состояние из подраздела 5.14; всё остальное создаётся и уничтожается внутри запроса.
- **WK-7.** `exit`, `die` и `set_exception_handler()` в воркере не используются: последний срабатывает при завершении скрипта воркера, а не после запроса.
- **WK-8.** Незакрытая транзакция невозможна по конструкции (FR-DATA-06); потерянное соединение восстанавливается (FR-DATA-07).

### 5.4. P4 — Прохождение конвейера

| Параметр | Значение |
| --- | --- |
| Вход | `ServerRequestInterface` |
| Результат | `ResponseInterface` |
| Требования | FR-MW-01..07, FR-ERR-01, FR-ERR-09, FR-SEC-01..05 |

**Сборка (P1, шаг 11.5).** Цепочка строится один раз справа налево:

```text
next = dispatcher
для звена из reverse(звенья):
    next = обработчик( запрос → звено.process(запрос, next) )
pipeline.handle = next.handle
```

**Выполнение.** Запрос идёт слева направо, ответ — справа налево (луковичная модель). Типовой порядок: `SecurityHeaders`, `ErrorHandler`, прикладные middleware.

| Случай | Путь запроса | Путь ответа | Итог |
| --- | --- | --- | --- |
| Штатный | `SecurityHeaders` → `ErrorHandler` → middleware → `Dispatcher` → контроллер | Назад по тем же звеньям; `SecurityHeaders` добавляет заголовки | Ответ контроллера с заголовками безопасности |
| Короткое замыкание в прикладном middleware | …→ middleware (возвращает ответ, `next` не вызван) | Через `ErrorHandler` и `SecurityHeaders` | Ответ звена |
| Исключение в контроллере или прикладном middleware | …→ точка броска | `ErrorHandler` перехватывает и формирует ответ (P10); `SecurityHeaders` дополняет его | Ответ об ошибке с заголовками безопасности |
| Исключение в самом `ErrorHandler` | — | Внутри `ErrorHandler`: 500 `text/plain` (FR-ERR-08) | Ответ 500 без оформления |
| Исключение в `SecurityHeaders` (аномалия) | — | Last resort в `Kernel` (FR-ERR-09) | 500 `text/plain`, `no-store`, `nosniff` |

**Почему `SecurityHeaders` стоит перед `ErrorHandler`.** Если бы `ErrorHandler` был самым внешним, его ответы об ошибках не проходили бы через `SecurityHeaders` и уходили бы без заголовков безопасности. Цена решения — звенья перед `ErrorHandler` не должны бросать исключений, поэтому они проще некуда и проверены тестами.

**Реентерабельность.** `Pipeline` не меняется после создания; несколько запросов могут идти через него одновременно (корутины), потому что `handle()` не хранит состояния.

### 5.5. P5 — Маршрутизация

| Параметр | Значение |
| --- | --- |
| Вход | Метод HTTP, путь (`UriInterface::getPath()`, в исходном процентном кодировании) |
| Результат | Пара `Route` и параметры пути; либо `HttpException` 400/404/405 |
| Требования | FR-ROUTE-01..11 |

**Фаза компиляции (при создании `Router`).**

```text
для каждого маршрута (в порядке объявления):
    проверить методы ∈ {GET, HEAD, POST, PUT, PATCH, DELETE, OPTIONS}
    разобрать шаблон на сегменты: статический текст | {имя} | {имя:выражение}
    проверить: шаблон начинается с «/»; имена уникальны и допустимы; у выражений нет захватывающих групп
    если параметров нет:  static[путь][метод] = маршрут              # поиск за O(1)
    иначе: regex = «#^» + Σ(preg_quote(статика) | (?P<имя>выражение или [^/]+)) + «$#Du»
           dynamic[] = (regex, маршрут)                              # порядок объявления сохраняется
    проверить уникальность пары (метод, шаблон) и имени маршрута; нарушение → InvalidArgumentException
```

**Фаза сопоставления.**

```text
match(метод, сырой_путь):
    путь = нормализовать(сырой_путь)                                 # см. ниже
    приемлемые = [метод] (+ GET, если метод = HEAD)
    разрешённые = {}                                                 # методы всех маршрутов, подошедших по пути
    1. если static[путь] существует:
           для (m, маршрут) в static[путь]: разрешённые += m; если m ∈ приемлемые → вернуть (маршрут, [])
    2. для (regex, маршрут) в dynamic по порядку:
           r = preg_match(regex, путь, найдено)
           если r === false → RuntimeException (ошибка PCRE, FR-ROUTE-11)
           если r = 1: разрешённые += маршрут.методы
                       если маршрут.методы ∩ приемлемые ≠ ∅ → параметры = только именованные группы → вернуть
    3. если разрешённые ≠ ∅ → HttpException 405, Allow = уникальные(разрешённые) ∪ {HEAD, если есть GET} ∪ {OPTIONS}, по алфавиту
    4. иначе → HttpException 404

нормализовать(сырой):
    пусто → «/»; не начинается с «/» → 400
    в сыром или декодированном виде есть байты 0x00–0x1F, 0x7F → 400
    декодирование rawurldecode выполняется один раз; результат не UTF-8 → 400
```

**Замечания.**

- Закодированный слэш `%2F` после декодирования становится разделителем сегментов; параметр, которому нужна косая черта, объявляется с ограничением (`{path:.+}`).
- Повторные слэши, регистр и завершающий слэш не нормализуются: `/a`, `/a/` и `//a` — разные пути.
- Приоритет статических маршрутов над динамическими не зависит от порядка объявления; порядок важен только между динамическими.
- `generate()` — обратная операция: подставляет значения в шаблон по имени маршрута, проверяя каждое значение ограничением параметра и кодируя его `rawurlencode`; лишний или недостающий параметр — `InvalidArgumentException`.

### 5.6. P6 — Диспетчеризация

| Параметр | Значение |
| --- | --- |
| Вход | `ServerRequestInterface` (конечный обработчик конвейера) |
| Результат | `ResponseInterface` действия контроллера; либо исключение |
| Требования | FR-DISP-01..09, FR-ROUTE-05, FR-ROUTE-06 |

```text
handle(запрос):
    1. путь = запрос.uri.path;  метод = запрос.method
    2. попытка (route, params) = router.match(метод, путь)
         при HttpException 405 и метод = OPTIONS → вернуть 204 с заголовком Allow из исключения    # FR-DISP-02
         иначе пробросить исключение
    3. запрос = запрос.withAttribute('asguard01.route', route).withAttribute('asguard01.route_params', params)
    4. (класс, действие) = route.handler;  для invokable-класса действие = '__invoke'
    5. контроллер = container.get(класс)                                    # P7
       если нет вызываемого (контроллер, действие) → LogicException
    6. план = кэш[класс::действие] или построить по рефлексии               # FR-DISP-08
    7. аргументы = для каждого параметра плана: запрос | значение параметра пути | значение по умолчанию | null
    8. ответ = контроллер.действие(...аргументы)
    9. если ответ не ResponseInterface → LogicException
   10. вернуть ответ
```

**Разрешение аргументов (FR-DISP-05, 06).**

| Параметр действия | Источник | Если не получается |
| --- | --- | --- |
| Тип `ServerRequestInterface` | Текущий запрос | — |
| Имя совпадает с параметром маршрута, тип `string` или без типа | Значение как строка | — |
| То же, тип `int` | `FILTER_VALIDATE_INT` | 404 |
| То же, тип `float` | `FILTER_VALIDATE_FLOAT` | 404 |
| То же, тип `bool` | `1`, `0`, `true`, `false` | 404 |
| Имени нет среди параметров маршрута | Значение по умолчанию; `null` для nullable | `LogicException` |
| Union, intersection, другие классы | — | `LogicException` при построении плана |

**Замечания.** Контроллер не получает контейнер и сервисы через аргументы действия; сервисы приходят только в конструктор. Исключения контроллера `Dispatcher` не перехватывает (FR-DISP-09). `HEAD` дошёл до `GET`-маршрута через `Router`; тело отрезает `Kernel` (FR-HTTP-04). Маршруты и обработчики — данные, а не код: поэтому нет вызова произвольных классов по URL (SEC-09).

### 5.7. P7 — Разрешение зависимостей

| Параметр | Значение |
| --- | --- |
| Вход | Идентификатор: имя класса, интерфейса или произвольная строка |
| Результат | Общий экземпляр сервиса; либо `NotFoundException` / `ContainerException` |
| Требования | FR-DI-01..10 |

```text
get(id) = resolve(id, цепочка = [])

resolve(id, цепочка):
    если id в экземплярах → вернуть его
    если id в цепочке     → ContainerException «circular dependency: A → B → A»
    цепочка' = цепочка + [id]
    если id в определениях:
        определение — строка (алиас)  → resolve(определение, цепочка')
        определение — Closure         → определение(view(цепочка'))     # фабрика получает представление контейнера
        иначе объект                  → сам объект
    иначе если существует инстанцируемый класс id → автоподстановка(id, цепочка')
    иначе → NotFoundException(id, цепочка)
    экземпляры[id] = результат;  вернуть результат

автоподстановка(класс, цепочка):
    конструктора нет → new класс
    для каждого параметра конструктора:
        именованный тип класса/интерфейса, has(тип)  → resolve(тип, цепочка)
        иначе есть значение по умолчанию (в том числе null) → оно
        иначе встроенный, union или intersection тип → ContainerException с подсказкой «добавьте фабрику»
        иначе → NotFoundException
        variadic → пустой набор
    new класс(...аргументы)
```

**Пример цепочки и цикла.**

```text
get(HomeController) → [HomeController] → View → [HomeController, View] → ResponseFactoryInterface → …
get(A) → [A] → B → [A, B] → C → [A, B, C] → A   ⇒  ContainerException: «A → B → C → A»
```

**Свойства.**

- Цепочка передаётся параметром, а не хранится в контейнере; два вложенных или приостановленных разрешения (Fiber) не портят друг друга.
- `get(ContainerInterface::class)` — `NotFoundException`: контейнер не регистрирует себя (FR-DI-07).
- Представление, переданное фабрике, действует только во время вызова фабрики; сохранять его запрещено (D-02).
- Сообщения исключений называют классы, параметры и цепочку, но никогда не значения.
- Из-за общего кэша экземпляров все сервисы — одиночки в рамках процесса; поэтому они обязаны быть без состояния (5.14).

### 5.8. P8 — Отрисовка шаблона

| Параметр | Значение |
| --- | --- |
| Вход | Имя шаблона, данные (`array<string, mixed>`), имя макета (`'layout'`, `null` — без макета) |
| Результат | Строка HTML (`render`) или `ResponseInterface` (`response`) |
| Требования | FR-VIEW-01..10, SEC-02 |

```text
render(имя, данные, макет = 'layout'):
    1. проверить имена переменных: допустимый идентификатор, не из {e, u, j, raw, include, content, this} → иначе InvalidArgumentException
    2. файл = путь_к_шаблонам/имя.php;  проверить имя по шаблону ^[A-Za-z0-9_-]+(/[A-Za-z0-9_-]+)*$
       realpath(файл) лежит внутри каталога шаблонов, файл существует → иначе InvalidArgumentException
    3. страница = отрисовать(файл, данные + хелперы)
    4. если макет ≠ null: вернуть отрисовать(макет, данные + хелперы + content = страница)
       иначе вернуть страница

отрисовать(файл, переменные):
    уровень = ob_get_level();  ob_start()
    попытка: изолированное замыкание: хелперы e, u, j, raw, include → extract(переменные) → require файл → вернуть ob_get_clean()
    при Throwable: закрыть все буферы выше «уровень»; пробросить исключение
```

**Хелперы шаблона** (подробности — FR-VIEW-04):

| Хелпер | Контекст | Реализация |
| --- | --- | --- |
| `$e($v)` | Текст HTML и значение атрибута в кавычках | `htmlspecialchars($v, ENT_QUOTES \| ENT_SUBSTITUTE \| ENT_HTML5, 'UTF-8')` |
| `$u($v)` | Компонент URL | `rawurlencode((string) $v)` |
| `$j($v)` | JSON внутри HTML или `<script>` | `json_encode` с `JSON_THROW_ON_ERROR`, `JSON_HEX_TAG`, `JSON_HEX_AMP`, `JSON_HEX_APOS`, `JSON_HEX_QUOT` |
| `$raw($v)` | Заведомо безопасная разметка | Возвращает строку как есть; нужен для поиска и ревью |
| `$include($имя, $данные)` | Фрагмент | Отрисовывает вложенный шаблон без макета и выводит сразу |

Шаблон не знает о контейнере, БД и сервисах (FR-VIEW-09). Данные — только скаляры, массивы и простые объекты, подготовленные контроллером. Контекстов, не покрытых хелперами (встроенный JavaScript, CSS, обработчики событий), следует избегать; если нужны — отдельный хелпер с тестами.

### 5.9. P9 — Доступ к данным

| Параметр | Значение |
| --- | --- |
| Вход | SQL (`literal-string`), параметры |
| Результат | Строки, число затронутых строк, идентификатор вставки |
| Требования | FR-DATA-01..08, SEC-01 |

```text
запрос(sql, params):
    1. pdo = соединение()                                  # лениво; сбой → RuntimeException без DSN и пароля
    2. stmt = pdo.prepare(sql)
    3. для каждого параметра: тип привязки по значению (FR-DATA-05); смешение именованных и позиционных → InvalidArgumentException
    4. stmt.execute()
    5. зависит от метода: rowCount | fetchAll | fetch | fetchColumn
    при PDOException: если соединение потеряно (SQLSTATE 08*, MySQL 2006/2013) → сбросить pdo и счётчик транзакций;
                      пробросить исключение (повтор операции не выполняется)
```

**Состояния соединения.**

```text
        ┌───────────┐ первое обращение  ┌────────────┐  transaction()   ┌─────────────────┐
старт ─▶│ без PDO   │──────────────────▶│ PDO открыт │─────────────────▶│ транзакция, n≥1 │
        └───────────┘                   │ n = 0      │◀─────────────────│ (глубина n)     │
              ▲                         └─────┬──────┘ commit / rollback└─────────────────┘
              └─── потеря соединения ───────────┘ (дескриптор и n сброшены)
```

```text
transaction(работа):
    если n = 0: pdo.beginTransaction()
    n += 1
    попытка: результат = работа(this)
    при Throwable: пометить «только откат»; n -= 1; если n = 0 → rollback и снять пометку; пробросить
    n -= 1
    если n = 0: если «только откат» → rollback, LogicException; иначе commit
    вернуть результат
```

Имена таблиц, столбцов и направление сортировки в SQL подставляются только из списка допустимых значений, жёстко заданного в коде; PHPStan с типом `literal-string` не пропускает строку, собранную из внешних данных (SEC-01).

### 5.10. P10 — Обработка ошибок

| Параметр | Значение |
| --- | --- |
| Вход | `Throwable` из нижележащих звеньев |
| Результат | Безопасный ответ об ошибке, запись в журнал |
| Требования | FR-ERR-01..12, FR-VIEW-10, SEC-05, SEC-06 |

```text
process(запрос, следующий):
    уровень = ob_get_level()
    попытка: вернуть следующий.handle(запрос)
    при Throwable e: вернуть ответ_об_ошибке(запрос, e, уровень)

ответ_об_ошибке(запрос, e, уровень):
    1. закрыть буферы вывода выше «уровень»; если что-то отброшено → журнал warning
    2. классификация:
         HttpException → статус, detail, заголовки из исключения
         иное Throwable → статус 500, detail пусто
    3. журнал: статус 4xx → info без трассировки; 5xx → error с исключением;
       контекст: method, path, status, [request_id]
    4. формат по Accept (шаг 5)
    5. тело:
         JSON: {"type":"about:blank","title":фраза,"status":N[,"detail":…]}, Content-Type: application/problem+json
         HTML: шаблон errors/<N> без макета; если нет или упал — встроенная страница с фразой
         debug: HTML с классом, сообщением, файлом, строкой, трассировкой (всё экранировано); JSON — член "debug"
    6. заголовки из исключения; для 5xx — Cache-Control: no-store
    при любом Throwable внутри шагов 1–6 («двойной сбой»):
         error_log(класс, сообщение, файл, строка);  вернуть 500 text/plain «Internal Server Error»
```

**Выбор формата по `Accept` (шаг 5).**

```text
html  = лучший (q, конкретность) среди диапазонов, подходящих для text/html:
        text/html → (q, 2);  text/* → (q, 1);  */* → (q, 0);  нет → (0, -1)
json  = лучший среди подходящих для application/problem+json или application/json:
        точное совпадение → (q, 2);  application/* → (q, 1);  */* → (q, 0);  нет → (0, -1)
заголовка Accept нет → считать «*/*»
выбрать JSON, если json.q > 0 и (json.q > html.q или (json.q = html.q и json.конкретность > html.конкретность)); иначе HTML
```

| `Accept` | Формат | Почему |
| --- | --- | --- |
| нет заголовка, `*/*` | HTML | Равенство, конкретность одинакова |
| `text/html,application/xhtml+xml,*/*;q=0.8` (браузер) | HTML | У HTML выше вес |
| `application/json` | JSON | HTML не допускается |
| `application/json, text/plain, */*` (типичный XHR-клиент) | JSON | Веса равны, у JSON диапазон конкретнее |
| `text/html, application/json` | HTML | Полное равенство |
| `application/json;q=0.5, text/html;q=0.8` | HTML | Вес HTML выше |

**Last resort в `Kernel`.** Исключение, дошедшее до `Kernel::handle()` (из звеньев перед `ErrorHandler` или из него самого), порождает 500 `text/plain` с телом `Internal Server Error`, заголовками `Cache-Control: no-store` и `X-Content-Type-Options: nosniff`; подробности пишутся только через `error_log()` (FR-ERR-09). Этот путь не использует контейнер, представления и логгер: от них могла произойти сама авария.

**Ответ не равен исключению.** Ответ 5xx, который контроллер вернул сам (не бросил), проходит конвейер как обычный ответ; `ErrorHandler` его не подменяет.

### 5.11. P11 — Журналирование

| Параметр | Значение |
| --- | --- |
| Вход | Уровень, сообщение, контекст (`array`) |
| Результат | Строка JSON в назначении журнала |
| Требования | FR-LOG-01..10, SEC-06 |

```text
log(уровень, сообщение, контекст):
    1. уровень не из восьми уровней RFC 5424 → Psr\Log\InvalidArgumentException
    2. ранг(уровень) > ранг(порог) → вернуть (запись отброшена)          # emergency=0 … debug=7
    3. попытка (никогда не бросать наружу):
         3.1 подставить {ключ} из контекста в сообщение (скаляры и Stringable)
         3.2 контекст = очистить(контекст, глубина 0)
         3.3 запись = {time: UTC RFC 3339 с микросекундами и «Z», level, message, context}
         3.4 json_encode(запись, UNESCAPED_UNICODE | UNESCAPED_SLASHES | INVALID_UTF8_SUBSTITUTE | PARTIAL_OUTPUT_ON_ERROR)
         3.5 длина > maxLength → усечь message и context, добавить пометку об усечении
         3.6 записать строку + «\n» одним вызовом (FR-LOG-10)
    при любом сбое: один резервный error_log(), тишина для вызывающего

очистить(значение, глубина, ключ):
    ключ содержит (без регистра) password | passwd | secret | token | authorization | cookie | api_key | apikey | dsn | credential → «[REDACTED]»
    скаляр: строка длиннее 2000 символов усекается; float NAN и INF → строка
    массив: глубина > 5 → «[max depth]»; больше 50 элементов → остальные заменяются пометкой «…(+N)»; значения очищаются рекурсивно
    Throwable в ключе «exception»: класс, сообщение, код, файл, строка, трассировка ≤ 30 кадров без аргументов, цепочка previous
    Stringable: строка (сбой __toString → «[unprintable Класс]»);  DateTimeInterface → ATOM;  UnitEnum → имя или значение
    прочие объекты → «[object Класс]»;  ресурс → «[resource тип]»;  Closure → «[object Closure]»
```

Перевод строки внутри значения экранирует JSON, поэтому поддельная запись через сообщение или контекст в журнал не попадает (SEC-06). Ротацию, хранение и пересылку выполняет среда (stdout/stderr контейнера, `logrotate`, агент сбора логов).

### 5.12. P12 — Отправка ответа

| Параметр | Значение |
| --- | --- |
| Вход | `ResponseInterface` |
| Результат | Статус, заголовки и тело переданы SAPI |
| Требования | FR-HTTP-03 |

```text
emit(ответ):
    1. headers_sent(файл, строка) → RuntimeException «Headers already sent in файл:строка»
    2. header_remove('X-Powered-By')
    3. header('HTTP/версия код фраза', replace = true, код)
    4. для каждого заголовка: первое значение — с заменой, остальные — без; Set-Cookie всегда без замены и без объединения
    5. нет Content-Length и Transfer-Encoding, размер тела известен, статус допускает тело → добавить Content-Length
    6. статус 1xx, 204, 205, 304 → тело не отправлять
    7. тело: rewind (если возможен); блоками по 8192 байта: echo read(8192) до eof
```

Эмиттер единственный (кроме composition root) вызывает `header()`, `headers_sent()` и `echo` (FR-HTTP-02). Значения заголовков проверяет реализация PSR-7 при создании; сам `header()` в PHP дополнительно отклоняет перевод строки — двойная защита от внедрения заголовков (response splitting).

### 5.13. Сквозные примеры

**Пример 1. `GET /posts/42`, `Accept: text/html`, маршрут `Route::get('/posts/{id:\d+}', [PostController::class, 'show'])`.**

| Шаг | Компонент | Что происходит | Значение |
| --- | --- | --- | --- |
| 1 | `index.php` | Запрос из суперглобальных переменных | `GET /posts/42` |
| 2 | `SecurityHeaders` | Пропускает запрос дальше | — |
| 3 | `ErrorHandler` | Запоминает уровень буферов, пропускает дальше | уровень = 0 |
| 4 | `Dispatcher` + `Router` | Статического маршрута нет; динамический подошёл | параметры `['id' => '42']` |
| 5 | `Container` | Создаёт `PostController` с зависимостями | цепочка `[PostController, PostRepository, Connection]` |
| 6 | `Dispatcher` | Приводит `id` к `int`, вызывает `show(int $id)` | `$id = 42` |
| 7 | Контроллер | Читает данные (P9), отрисовывает шаблон (P8) | `200`, `text/html; charset=UTF-8` |
| 8 | `ErrorHandler` | Ответ без исключения проходит как есть | — |
| 9 | `SecurityHeaders` | Добавляет заголовки безопасности | CSP, `nosniff`, … |
| 10 | `Kernel` | Метод не `HEAD`, ответ возвращается | — |
| 11 | `ResponseEmitter` | Статус, заголовки, `Content-Length`, тело | — |

**Пример 2. `GET /posts/abc`.** Шаблон `\d+` не подходит; других маршрутов для пути нет → `HttpException` 404 → `ErrorHandler`: журнал `info`, HTML из `errors/404` (или JSON при `Accept: application/json`) → `SecurityHeaders` → ответ 404.

**Пример 3. `DELETE /posts/42` при существующем `GET`-маршруте.** Путь подошёл, метод — нет → `HttpException` 405, `Allow: GET, HEAD, OPTIONS` → 405 с этим заголовком (FR-ERR-11).

**Пример 4. Необработанное исключение в контроллере.** `ErrorHandler` закрывает лишние буферы, пишет `error` с трассировкой в JSON Lines, отвечает 500 с нейтральным телом и `Cache-Control: no-store`; в теле нет текста исключения.

**Пример 5. `HEAD /`.** Router выбирает `GET`-маршрут; `Kernel` фиксирует `Content-Length`, заменяет тело пустым; клиент получает заголовки без тела.

#### 6.1.2. `bootstrap.php`

| Параметр | Значение |
| --- | --- |
| Назначение | Собирает приложение (P1) и возвращает `Kernel` |
| Зависит от | Всё; это composition root |
| Требования | FR-ENTRY-05, FR-ENTRY-06, FR-CFG-07, FR-ERR-10, FR-MW-05 |
| Тесты | T-ENTRY-01..04, T-ERR-14 |

```php
<?php

declare(strict_types=1);

use Asguard01\PhpMvc\Config\Config;
use Asguard01\PhpMvc\Config\Env;
use Asguard01\PhpMvc\Container\Container;
use Asguard01\PhpMvc\Kernel;
use Psr\Http\Message\ResponseFactoryInterface;
use Psr\Http\Message\StreamFactoryInterface;

$basePath = __DIR__;

require $basePath . '/vendor/autoload.php';

error_reporting(E_ALL);
ini_set('display_errors', '0');
date_default_timezone_set('UTC');
mb_internal_encoding('UTF-8');

set_error_handler(static function (int $severity, string $message, string $file, int $line): bool {
    if ((error_reporting() & $severity) === 0) {
        return false;
    }

    if (($severity & (E_DEPRECATED | E_USER_DEPRECATED)) !== 0) {
        error_log(sprintf('Deprecated: %s in %s:%d', $message, $file, $line));

        return true;
    }

    throw new ErrorException($message, 0, $severity, $file, $line);
});

$env = Env::load($basePath . '/.env');
$config = Config::load($basePath . '/config', $env, $basePath);

$appEnv = $config->string('app.env');
if (!in_array($appEnv, ['dev', 'test', 'prod'], true)) {
    throw new LogicException('Invalid value of app.env.');
}
if ($appEnv === 'prod' && $config->bool('app.debug')) {
    throw new LogicException('Debug mode must be disabled when app.env is prod.');
}

/** @var Closure(Config, string): array<string, mixed> $definitions */
$definitions = require $basePath . '/config/container.php';
$container = new Container($definitions($config, $basePath));

/** @var list<class-string<Psr\Http\Server\MiddlewareInterface>> $middleware */
$middleware = require $basePath . '/config/middleware.php';

$responses = $container->get(ResponseFactoryInterface::class);
$streams = $container->get(StreamFactoryInterface::class);
assert($responses instanceof ResponseFactoryInterface && $streams instanceof StreamFactoryInterface);

return new Kernel($container, $middleware, $responses, $streams);
```

### 6.4. Каталог `src/` — ядро

#### 6.4.1. `src/Kernel.php`

| Параметр | Значение |
| --- | --- |
| Назначение | Ядро — `RequestHandlerInterface` (PSR-15): собирает конвейер (P1, шаг 11), обрабатывает запрос (P4), отрезает тело у `HEAD`, формирует last resort |
| Класс | `final readonly class Kernel`, `@api` |
| Зависит от | `psr/container`, `psr/http-*`, `Asguard01\PhpMvc\Middleware\{Pipeline, ErrorHandler}`, `Asguard01\PhpMvc\Routing\{Router, Dispatcher}` |
| Требования | FR-MW-02, FR-MW-05, FR-MW-06, FR-HTTP-04, FR-ERR-09, D-02 |
| Тесты | T-MW-06..08, T-ERR-13, `KernelTest` |

```php
<?php

declare(strict_types=1);

namespace Asguard01\PhpMvc;

use Psr\Container\ContainerInterface;
use Psr\Http\Message\ResponseFactoryInterface;
use Psr\Http\Message\ResponseInterface;
use Psr\Http\Message\ServerRequestInterface;
use Psr\Http\Message\StreamFactoryInterface;
use Psr\Http\Server\MiddlewareInterface;
use Psr\Http\Server\RequestHandlerInterface;

/** @api */
final readonly class Kernel implements RequestHandlerInterface
{
    private RequestHandlerInterface $pipeline;

    /**
     * @param list<class-string<MiddlewareInterface>> $middleware
     *
     * @throws \LogicException если список middleware некорректен
     */
    public function __construct(
        ContainerInterface $container,
        array $middleware,
        private ResponseFactoryInterface $responses,
        private StreamFactoryInterface $streams,
    ) {}

    /** Не бросает исключений: любая ошибка превращается в ответ 500. */
    #[\Override]
    public function handle(ServerRequestInterface $request): ResponseInterface {}
}
```

**Конструктор** (P1, шаг 11): получает `Router` из контейнера; создаёт `Dispatcher` (контейнером он не создаётся — ему нужна «настоящая» ссылка на контейнер, а не представление); получает каждый middleware из контейнера в порядке списка; проверяет `instanceof MiddlewareInterface` и ровно одно вхождение `ErrorHandler`; создаёт `Pipeline`. Ссылку на контейнер не сохраняет.

**`handle()`.**

1. Вызывает `Pipeline::handle()`.
2. Для метода `HEAD`: если у ответа нет `Content-Length`, размер тела известен, а статус допускает тело — добавляет `Content-Length`; затем заменяет тело пустым потоком (FR-HTTP-04).
3. Любое `Throwable` перехватывает: `error_log(sprintf('Unhandled %s: %s in %s:%d', класс, сообщение, файл, строка))` и возвращает last resort — 500, `Content-Type: text/plain; charset=UTF-8`, `Cache-Control: no-store`, `X-Content-Type-Options: nosniff`, тело `Internal Server Error` (FR-ERR-09).

**Запрещено.** Использовать PSR-3-логгер в last resort (авария могла случиться в самом логгере); обращаться к суперглобальным; хранить запрос. Отказ фабрик PSR-17 не перехватывается (FR-ERR-09).

#### 6.4.2. `src/Http/HttpException.php`

| Параметр | Значение |
| --- | --- |
| Назначение | Единственный способ сообщить клиенту об ошибке 4xx/5xx из кода приложения |

Сообщение исключения (`getMessage()`) — служебное, на английском: `HTTP <статус>` и, если есть, `: <detail>`. `methodNotAllowed()` задаёт статус 405 и заголовок `Allow` (значения через запятую в порядке аргумента).

| Параметр | Значение |
| --- | --- |
| Назначение | Отправка `ResponseInterface` через SAPI (P12) |
| Класс | `final readonly class ResponseEmitter`, `@api` |
| Зависит от | `psr/http-message` |
| Требования | FR-HTTP-02, FR-HTTP-03 |
| Тесты | T-HTTP-06..15 (E2E и раздельные процессы) |

| --- | --- | --- |
| Пустая строка, комментарий | `# текст` | Пропускается |
| Без кавычек | `APP_ENV=dev` | `dev` (пробелы по краям обрезаются) |
| Комментарий после значения | `APP_ENV=dev # комментарий` | `dev` (комментарий начинается с пробела и `#`) |
| Префикс `export` | `export APP_ENV=dev` | `dev` |
| Одинарные кавычки | `KEY='a #b $c\n'` | Буквально: `a #b $c\n` |
| Двойные кавычки | `KEY="a\nb \"q\" \\"` | Поддерживаются `\n`, `\r`, `\t`, `\"`, `\\`; прочие `\` — буквально |
| Пустое значение | `DB_PASSWORD=` | Пустая строка (переменная задана) |
| Знак равенства в значении | `DB_DSN=mysql:host=h;dbname=d` | Делится по первому `=` |
| Ошибка | `1KEY=x`, `KEY` без `=`, незакрытая кавычка, текст после закрывающей кавычки | `UnexpectedValueException` с файлом и номером строки, без значения |

**Приоритет и поведение.** Значения процесса перекрывают значения файла. Отсутствие файла `.env` — не ошибка; файл, который существует, но не читается, — `RuntimeException`. `get()` возвращает `null`, если переменной нет и не передан `$default`. `string()`: пустая задана → пустая строка. `bool()`: принимает `1`, `true`, `on`, `yes` и `0`, `false`, `off`, `no` без учёта регистра; пустое значение считается незаданным и даёт `$default`. `int()`: проверка `FILTER_VALIDATE_INT`; пустое значение даёт `$default`. `__debugInfo()` возвращает только имена. `__serialize()` бросает `LogicException`: значения не должны попадать в кэши и сессии. Класс не вызывает `putenv()`, не читает `$_ENV` и `$_SERVER` (FR-CFG-02).

/** @api */

**Структуры (рекомендуемые).** Таблица статических маршрутов `путь → [метод → Route]`; список динамических `(регулярное выражение, Route, имена параметров)` в порядке объявления; таблица имён `имя → Route`.

**Правила.**

- Разбор шаблона: `{имя}` и `{имя:выражение}`; допускается один уровень вложенных фигурных скобок в выражении (квантификаторы `\d{1,3}`). Выражение без захватывающих групп (способ проверки — на усмотрение реализации). Статические части экранируются `preg_quote()`, разделитель выражения экранируется.
- Итоговое выражение: `#^…$#Du` — привязка к началу и концу (`D` запрещает совпадение перед завершающим переводом строки), режим UTF-8.

- Заголовок `Allow` (FR-ROUTE-06): уникальные методы в алфавитном порядке; `HEAD` добавляется при наличии `GET`; `OPTIONS` — всегда.
- `generate()`: значение параметра проверяется ограничением параметра целиком (`^…$`) и кодируется `rawurlencode()`; результат всегда начинается с `/`; хост и схема не добавляются; параметры запроса — `http_build_query(…, '', '&', PHP_QUERY_RFC3986)`.
- Объект неизменяем и потокобезопасен; повторный вызов `match()` с теми же аргументами даёт тот же результат.

```php
<?php

declare(strict_types=1);

namespace Asguard01\PhpMvc\View;

use Psr\Http\Message\ResponseFactoryInterface;
use Psr\Http\Message\ResponseInterface;
use Psr\Http\Message\StreamFactoryInterface;

/** @api */
final readonly class View
{
    /** @throws \InvalidArgumentException если каталог шаблонов не существует */
    public function __construct(
        private string $viewsPath,
        private ResponseFactoryInterface $responses,
        private StreamFactoryInterface $streams,
    ) {}

    /**
     * @param array<string, mixed> $data
     *
     * @throws \InvalidArgumentException если имя шаблона или имена переменных недопустимы либо шаблона нет
     */
    public function render(string $template, array $data = [], ?string $layout = 'layout'): string {}

    /**
     * @param array<string, mixed> $data
     *
     * @throws \InvalidArgumentException
     */
    public function response(string $template, array $data = [], int $status = 200, ?string $layout = 'layout'): ResponseInterface {}

    public function exists(string $template): bool {}
}
```

**Правила.**

- Путь к каталогу шаблонов нормализуется `realpath()` при создании; итоговый путь шаблона после `realpath()` обязан лежать внутри каталога (защита от выхода за пределы, SEC-10).
- Файл шаблона подключается внутри изолированного статического замыкания: в нём доступны только переменные данных, хелперы (`$e`, `$u`, `$j`, `$raw`, `$include`) и, для макета, `$content`; `$this` недоступен.
- `response()` создаёт ответ фабрикой PSR-17, заголовок `Content-Type: text/html; charset=UTF-8`, тело — поток из строки HTML.
- `exists()` проверяет имя по шаблону и наличие файла; не бросает исключений.
- Закрытие буферов вывода при исключении обязательно (`finally` или `catch`).

#### 6.4.15. `src/Database/Connection.php`

| Параметр | Значение |
| --- | --- |
| Назначение | Тонкая обёртка над PDO: подготовленные запросы, выборки, транзакции (P9) |
| Класс | `final class Connection`, `@api` (изменяемое состояние: дескриптор PDO и глубина транзакции) |
| Зависит от | Только PHP (`ext-pdo`) |
| Требования | FR-DATA-01..08, SEC-01 |
| Тесты | T-DATA-01..12 (SQLite в памяти) |

```php
<?php

declare(strict_types=1);

namespace Asguard01\PhpMvc\Database;

/** @api */
final class Connection
{
    /**
     * @param array<int, mixed> $options Дополнительные параметры PDO (перекрывают значения по умолчанию)
     * @param (\Closure(): \PDO)|null $factory Точка подмены создания PDO (тесты, особые драйверы)
     */
    public function __construct(
        private readonly string $dsn,
        private readonly ?string $username = null,
        #[\SensitiveParameter]
        private readonly ?string $password = null,
        private readonly array $options = [],
        private readonly ?\Closure $factory = null,
    ) {}

    /**
     * @param literal-string $sql
     * @param array<int|string, scalar|\Stringable|resource|null> $params
     *
     * @return int Число затронутых строк
     */
    public function execute(string $sql, array $params = []): int {}

    /**
     * @param literal-string $sql
     * @param array<int|string, scalar|\Stringable|resource|null> $params
     *
     * @return list<array<string, mixed>>
     */
    public function fetchAll(string $sql, array $params = []): array {}

    /**
     * @param literal-string $sql
     * @param array<int|string, scalar|\Stringable|resource|null> $params
     *
     * @return array<string, mixed>|null
     */
    public function fetchOne(string $sql, array $params = []): ?array {}

    /**
     * Первый столбец первой строки; null, если строк нет.
     *
     * @param literal-string $sql
     * @param array<int|string, scalar|\Stringable|resource|null> $params
     */
    public function fetchValue(string $sql, array $params = []): mixed {}

    public function lastInsertId(?string $name = null): string {}

    /**
     * @template T
     *
     * @param callable(self): T $work
     *
     * @return T
     */
    public function transaction(callable $work): mixed {}
}
```

**Правила.**

- Параметры PDO по умолчанию: `ERRMODE_EXCEPTION`, `FETCH_ASSOC`, `EMULATE_PREPARES = false`, `STRINGIFY_FETCHES = false`, `PERSISTENT = false` (FR-DATA-03).
- Типы привязки значений — FR-DATA-05; массивы и объекты без `__toString()` — `InvalidArgumentException`; смешение именованных и позиционных параметров — `InvalidArgumentException`.
- Ошибка подключения оборачивается в `RuntimeException('Unable to connect to the database.')` без DSN, имени пользователя, пароля и без `previous` (FR-DATA-08); исходная причина пишется только в `error_log()` в виде класса и кода ошибки.
- Потеря соединения (SQLSTATE класса `08`, коды драйвера 2006 и 2013) сбрасывает дескриптор PDO, глубину транзакции и флаг «только откат»; операция не повторяется (FR-DATA-07).
- Публичных методов `begin`, `commit`, `rollback` нет; `transaction()` — алгоритм подраздела 5.9.
- Метод `fetchValue()` не отличает отсутствие строки от значения `NULL`: если различие важно, используется `fetchOne()`.
- Классы-модели и репозитории не наследуют `Connection` (класс `final`).

| --- | --- |
| Назначение | Журнал PSR-3: JSON Lines в поток или файл (P11) |
| Класс | `final class FileLogger extends AbstractLogger`, `@api` |
| Зависит от | `psr/log` |
| Требования | FR-LOG-01..10, SEC-06 |
| Тесты | T-LOG-01..14 |

```php
<?php

declare(strict_types=1);

namespace Asguard01\PhpMvc\Log;

use Psr\Log\AbstractLogger;
use Psr\Log\LogLevel;

/** @api */
final class FileLogger extends AbstractLogger
{
    /**
     * @param string $destination php://stderr, php://stdout или путь к файлу
     * @param string $level Порог: записи менее важные отбрасываются
     * @param (\Closure(): \DateTimeImmutable)|null $clock Источник времени (UTC); null — системные часы
     * @param int $maxLength Предельная длина записи в байтах
     *
     * @throws \Psr\Log\InvalidArgumentException если порог не является уровнем PSR-3
     */
    public function __construct(
        private readonly string $destination,
        private readonly string $level = LogLevel::INFO,
        private readonly ?\Closure $clock = null,
        private readonly int $maxLength = 16384,
    ) {}

    /**
     * @param array<array-key, mixed> $context
     *
     * @throws \Psr\Log\InvalidArgumentException если уровень неизвестен
     */

```

**Правила.** Алгоритм и очистка контекста — подраздел 5.11. Единственное исключение, которое метод может бросить, — `Psr\Log\InvalidArgumentException` для неизвестного уровня (требование PSR-3); всё остальное (недоступный файл, кодирование JSON, `__toString()` с исключением) заканчивается резервным вызовом `error_log()`. Поток `php://stderr` и `php://stdout` открывается лениво, один раз, и переиспользуется в воркере; файл пишется вызовом `file_put_contents()` с `FILE_APPEND | LOCK_EX`. Каталог файла журнала логгер не создаёт: это забота развёртывания (подраздел 10.4). Время берётся из `$clock` или системных часов и приводится к UTC. Не сериализует объекты, кроме перечисленных в 5.11.

## 7. Нефункциональные требования

### 7.1. Требования безопасности

**Границы ответственности.** Ядро отвечает за безопасную обработку запроса, вывода, данных, ошибок и журнала. Аутентификация, авторизация, CSRF-защита, сессии, CORS и ограничение частоты запросов не входят в версию 1.0: они подключаются как middleware (раздел 11) и не требуют правки ядра.

**Основания.** [OWASP Top 10:2025](https://owasp.org/Top10/2025/0x00_2025-Introduction/); [OWASP ASVS 5.0.0](https://owasp.org/www-project-application-security-verification-standard/) как справочник проверок (формальная оценка уровня соответствия ASVS вне объёма версии 1.0); [OWASP Cheat Sheet Series](https://cheatsheetseries.owasp.org/) — SQL Injection Prevention, Cross Site Scripting Prevention, HTTP Headers, PHP Configuration, Logging, Error Handling.

#### 7.1.1. Соответствие OWASP Top 10:2025

| Категория | Что делает ядро | Требования | Что остаётся приложению |
| --- | --- | --- | --- |
| A01:2025 Нарушение контроля доступа (Broken Access Control) | Только объявленные маршруты и методы; веб-корень — `public/`; скрытые файлы закрыты; имя шаблона проверяется | SEC-09, SEC-10 | Аутентификация и авторизация как middleware; проверка прав на объекты; CORS |
| A02:2025 Небезопасная конфигурация (Security Misconfiguration) | Безопасные значения по умолчанию; инвариант «prod — без отладки»; заголовки безопасности; эталонные настройки PHP и серверов | SEC-03, SEC-04, SEC-16 | Настройки веб-сервера, ОС, СУБД |
| A03:2025 Сбои в цепочке поставок ПО (Software Supply Chain Failures) | Минимум зависимостей; `composer.lock`; аудит зависимостей в CI | SEC-07 | Выбор зависимостей приложения; SBOM; подпись артефактов |
| A04:2025 Криптографические сбои (Cryptographic Failures) | Ядро не содержит криптографии; в production обязателен TLS и HSTS | SEC-08 | Хеширование паролей, шифрование данных, ключи |

| A10:2025 Неправильная обработка исключительных ситуаций (Mishandling of Exceptional Conditions) | Безопасный отказ; last resort; нейтральные ответы; откат транзакций; закрытие буферов | SEC-05, SEC-16 | Обработка ошибок предметной области |

#### 7.1.2. Требования

- **SEC-01 (A05). SQL-инъекции.** Запросы выполняются только как подготовленные, с привязкой параметров и `EMULATE_PREPARES=false`; параметр SQL имеет тип `literal-string`; идентификаторы SQL (таблицы, столбцы, направление сортировки) берутся из списка допустимых значений в коде; PDO вне `src/Database` не используется. *Проверка:* T-DATA-02..04, T-DATA-12, T-ARCH-06, PHPStan.
- **SEC-02 (A05). Внедрение в HTML.** Вывод экранируется по контексту хелперами `$e`, `$u`, `$j`; `$raw` применяется только к заведомо безопасной разметке и подлежит ревью; все `<?=` в шаблонах проверяются тестом. *Проверка:* T-VIEW-03..05, T-VIEW-11.
- **SEC-03 (A02). Безопасная конфигурация по умолчанию.** `APP_ENV=prod`, `APP_DEBUG=false`; при `prod` и `debug=true` приложение не стартует; `display_errors=0` устанавливается в `bootstrap.php`; `.env`, `vendor/`, `config/`, `storage/` и исходный код недоступны по URL; скрытые файлы закрыты; `X-Powered-By` удаляется. *Проверка:* T-ENTRY-02, T-ENTRY-03, T-HTTP-09, T-E2E-06, T-E2E-07.
- **SEC-04 (A02). Заголовки безопасности.** Каждый ответ, включая ответы об ошибках, получает заголовки из приложения B; заголовок, заданный обработчиком, не перезаписывается; `X-XSS-Protection` не отправляется. *Проверка:* T-SEC-01..08, T-E2E-01.
- **SEC-05 (A10). Безопасный отказ.** Любое неперехваченное исключение даёт 500 без технических подробностей; ошибки PHP становятся исключениями; пустые `catch` и оператор `@` запрещены; при двойном сбое и в last resort возвращается минимальный ответ; открытые буферы вывода закрываются, транзакции откатываются. *Проверка:* T-ERR-01..14, T-DATA-07, T-DATA-08, T-ARCH-03.
- **SEC-06 (A09). Журналирование.** Журнал — JSON Lines через PSR-3; значения по ключам из списка секретов заменяются на `[REDACTED]`; перевод строки внутри данных не создаёт поддельных записей; в журнал не попадают тела запросов, заголовки, `Cookie`, `Authorization`, строка запроса; ошибки 5xx пишутся на уровне `error` с исключением, ошибки 4xx — на уровне `info` без трассировки. *Проверка:* T-LOG-01..14, T-ERR-01, T-ERR-02.
- **SEC-07 (A03). Цепочка поставок.** Зависимости времени выполнения ограничены подразделом 2.3; новая зависимость требует записи архитектурного решения; `composer.lock` хранится в репозитории; CI выполняет `composer audit` и падает при уязвимостях; блокировка небезопасных версий Composer (`audit.block-insecure`, Composer 2.9+) не отключается; обновление зависимостей по расписанию — рекомендация. *Проверка:* CI, подраздел 8.4.
- **SEC-08 (A04). Криптография.** Ядро не реализует криптографию и не хранит ключи. В production трафик идёт только по TLS, `Strict-Transport-Security` включён. Для случайных значений приложение использует `random_bytes()` и `random_int()`, для паролей — `password_hash()` и `password_verify()`; `md5()` и `sha1()` для защиты секретов запрещены. *Проверка:* T-SEC-04, ревью.
- **SEC-09 (A06). Запрет по умолчанию.** Выполняется только то, что объявлено в `config/routes.php`; автомаршрутизации «URL → класс → метод» нет; обработчики маршрутов — данные, а не замыкания; допускаются семь методов HTTP; каждый класс `final`. *Проверка:* T-DISP-01, T-ROUTE-02, T-ARCH-05.
- **SEC-10 (A01). Доступ к файлам и шаблонам.** Веб-корень — только `public/`; имя шаблона не строится из пользовательского ввода и проверяется регулярным выражением и `realpath()`; индексирование каталогов выключено. *Проверка:* T-VIEW-07, T-E2E-06.
- **SEC-11 (A07). Аутентификация (вне ядра).** Расширение аутентификации реализуется как middleware PSR-15 после `ErrorHandler`; cookie сессии — `HttpOnly`, `Secure`, `SameSite`; идентификатор сессии меняется при смене привилегий; секреты не передаются в URL; для входа действует ограничение частоты. Требования — для будущих расширений (раздел 11).
- **SEC-12 (A08). Целостность.** В `src/` и `app/` запрещены `eval`, `unserialize()` для данных извне и динамический `include` (кроме шаблонов и конфигурации по проверенным путям); `extract()` разрешён только в `View`; сериализация `Env` и `Config` запрещена. *Проверка:* T-ARCH-03, T-CFG-09, T-CFG-19.
- **SEC-13. Лимиты ввода.** Размеры тела, число полей и время обработки ограничиваются веб-сервером и PHP (`client_max_body_size`, `post_max_size`, `max_input_vars`, `max_execution_time`; значения — в приложении E и подразделе 10.2); ядро не читает тело запроса целиком, это делает приложение. *Проверка:* приёмка конфигурации, подраздел 10.2.
- **SEC-14. Недоверие к `Host` и `X-Forwarded-*`.** Ядро не принимает решений по этим заголовкам: URL строятся относительными путями (`Router::generate()`), решение о HSTS принимается по параметру сервера `HTTPS` (FR-SEC-03). Доверие к прокси — расширение. *Проверка:* T-SEC-04, T-ROUTE-13.
- **SEC-15. Устойчивость к отказу в обслуживании.** Регулярные выражения маршрутов компилируются при старте, ошибка PCRE превращается в 500, а не в тихий пропуск (FR-ROUTE-11); запись журнала ограничена по размеру; цепочка контейнера защищена от бесконечной рекурсии; рекомендуется не использовать в ограничениях маршрутов вложенные неограниченные квантификаторы. *Проверка:* T-ROUTE-12, T-LOG-08, T-DI-07.
- **SEC-16. Отсутствие утечек информации.** Тела ответов 5xx содержат только фразу статуса; нет баннеров версий (`expose_php=Off`, `X-Powered-By` удалён); отладочные сведения доступны только при `app.debug` вне production. *Проверка:* T-ERR-02, T-ERR-03, T-ERR-09, T-E2E-07.

### 7.2. Прочие нефункциональные требования

#### Производительность (NFR-PERF)

Числовые значения — ориентиры (SHOULD): они не измерялись и уточняются по результатам замеров на этапе 5; обязательны методика и отчёт.

- **NFR-PERF-01.** Методика: маршрут `GET /` (`HomeController`, без БД), PHP 8.5, `opcache` включён, `opcache.validate_timestamps=0`, одно ядро процессора; нагрузочный инструмент — на выбор исполнителя; результаты и условия — в `docs/benchmarks.md`.
- **NFR-PERF-02.** Накладные расходы ядра на запрос: в воркере — порядка 0,5 мс процессорного времени, в классическом режиме с `opcache` — порядка 3 мс (ориентир).
- **NFR-PERF-03.** Пиковая память запроса `GET /` сверх базового потребления PHP — порядка 4 МиБ (ориентир).
- **NFR-PERF-04.** Время сопоставления маршрута не растёт быстрее чем линейно по числу динамических маршрутов; статические маршруты находятся за константное время.
- **NFR-PERF-05 (MUST).** В воркере нет монотонного роста памяти: прирост после прогрева и `gc_collect_cycles()` за 10 000 запросов не превышает порога, закреплённого в тесте T-WK-03 (по умолчанию 1 МиБ).

#### Надёжность (NFR-REL)

- **NFR-REL-01.** Штатные ошибки приложения не приводят к фатальным ошибкам PHP: все они выражены исключениями и обрабатываются (P10).
- **NFR-REL-02.** Недоступный или заполненный журнал не нарушает обработку запроса: логгер не бросает исключений (FR-LOG-08).
- **NFR-REL-03.** Потеря соединения с БД не оставляет воркер в неработоспособном состоянии (FR-DATA-07).
- **NFR-REL-04.** Ошибка одного запроса не влияет на следующие в том же процессе (T-WK-06).
- **NFR-REL-05.** Старт приложения детерминирован: одинаковые входные данные дают одинаковый граф объектов; ошибки конфигурации выявляются при старте (D-06).

#### Сопровождаемость (NFR-MNT)

- **NFR-MNT-01.** PHPStan, уровень 10 (`max`), без baseline-файла и без игнорирования ошибок в конфигурации.
- **NFR-MNT-02.** Стиль — `@PER-CS3x0` и `declare_strict_types`; `php-cs-fixer` в режиме проверки не находит отличий.
- **NFR-MNT-03.** Покрытие строк в `src/` — не менее 90 %, в `app/` — не менее 80 %.
- **NFR-MNT-04 (SHOULD).** Показатель мутационного тестирования (MSI) в `src/` — не менее 70 %; инструмент и версия — по подразделу 2.4.
- **NFR-MNT-05 (SHOULD).** Цикломатическая сложность метода — не более 10; превышение объясняется комментарием или записью архитектурного решения.
- **NFR-MNT-06.** Каждый класс и метод `@api` описан в PHPDoc: назначение, параметры, исключения.
- **NFR-MNT-07.** Любое отступление от этого документа оформляется записью архитектурного решения в `docs/adr/` (раздел 9).

#### Наблюдаемость (NFR-OBS)

- **NFR-OBS-01.** Журнал структурирован (FR-LOG-02) и пригоден для разбора без регулярных выражений (`jq` и аналоги).
- **NFR-OBS-02.** Каждая необработанная ситуация оставляет запись с классом исключения, сообщением, файлом, строкой и усечённой трассировкой без аргументов.
- **NFR-OBS-03.** Идентификатор запроса и контекст трассировки подключаются middleware через атрибут запроса `request_id` (FR-ERR-12); формат — W3C Trace Context.
- **NFR-OBS-04.** Метрики, трассировка и проверки работоспособности — вне ядра; точки подключения описаны в разделе 11.

#### Переносимость (NFR-PORT)

- **NFR-PORT-01.** Основная платформа — Linux; macOS и Windows допускаются для разработки. Пути формируются с прямым слэшем; регистр имён файлов значим.
- **NFR-PORT-02.** Среды запуска — по подразделу 2.5; код ядра не зависит от SAPI.
- **NFR-PORT-03.** Драйверы БД — любые из PDO (MySQL/MariaDB, PostgreSQL, SQLite); ядро не содержит SQL, специфичного для драйвера, кроме проверки кодов потери соединения. Тесты выполняются на SQLite; интеграционные тесты на MySQL и PostgreSQL — рекомендуются (SHOULD).

#### Интернационализация и доступность (NFR-I18N, NFR-A11Y)

- **NFR-I18N-01.** Все данные и файлы — UTF-8; строковые операции над текстом — `mb_*`.
- **NFR-I18N-02.** Сообщения исключений и записи журнала — на английском; тексты страниц-примеров — на русском; локализация интерфейса — расширение.
- **NFR-A11Y-01.** Шаблоны каркаса — валидный HTML5: `lang`, `meta charset`, `meta viewport`, `title`, семантические элементы (`main`, `h1`).

#### Документация (NFR-DOC)

- **NFR-DOC-01.** `readme.md` — по подразделу 6.1.5.
- **NFR-DOC-02.** `docs/adr/` — записи архитектурных решений по шаблону «контекст — решение — последствия».
- **NFR-DOC-03.** `CHANGELOG.md` по NFR-API-03 и `SECURITY.md` с порядком сообщения об уязвимостях.
- **NFR-DOC-04.** Руководство по расширению `docs/extending.md`: как подключить middleware, добавить маршрут, сервис и шаблон ошибки.

#### Лицензия (NFR-LIC)

- **NFR-LIC-01.** Лицензия определяется владельцем проекта до выпуска 1.0.0 (риск R-08). До решения в `composer.json` указывается `"license": "proprietary"`; при выборе открытой лицензии добавляются файл `LICENSE` и идентификатор SPDX.

## 8. Тестирование и контроль качества

### 8.1. Стратегия

| Уровень | Что проверяет | Инструменты | Расположение | Обязательность |
| --- | --- | --- | --- | --- |
| Модульный | Один класс в изоляции | PHPUnit 12 | `tests/Unit/` | Обязательно |
| Интеграционный | Ядро целиком: `Kernel`, реальный контейнер, `nyholm/psr7`, SQLite | PHPUnit | `tests/Integration/` | Обязательно |
| Контрактный | Сигнатуры из раздела 6 и совместимость с PSR | PHPUnit, Reflection | `tests/Architecture/ContractTest.php` | Обязательно |
| Архитектурный | Правила зависимостей, запрещённые конструкции, состояние | PHPUnit, `token_get_all()` | `tests/Architecture/` | Обязательно |
| Безопасности воркера | Отсутствие утечек между запросами | PHPUnit | `tests/Integration/WorkerSafetyTest.php` | Обязательно |
| Сквозной (E2E) | Реальный HTTP-обмен со встроенным сервером PHP | PHPUnit, `proc_open` | `tests/E2E/` | Обязательно |
| Статический анализ | Типы, мёртвый код, запрещённые вызовы | PHPStan | Конфигурация `phpstan.neon.dist` | Обязательно |
| Стиль | PER Coding Style | php-cs-fixer | `.php-cs-fixer.dist.php` | Обязательно |
| Мутационный | Сила тестов | Infection (не проверено) | Конфигурация инструмента | Рекомендуется |
| Производительность | Замеры накладных расходов | Скрипт и нагрузчик | `docs/benchmarks.md` | Обязательно один раз на этапе 5 |

**Принципы.**

- Тесты детерминированы: время и случайность подменяются; нет `sleep`; нет обращений к сети, кроме петлевого интерфейса в E2E.
- Тесты независимы: порядок запуска не влияет на результат; состояние процесса не разделяется (PHPUnit с `executionOrder="random"`).
- Метаданные тестов — атрибутами PHPUnit (`#[Test]`, `#[DataProvider]`, `#[CoversClass]`, `#[RunInSeparateProcess]`).
- Один тест — одно наблюдаемое поведение; имя описывает поведение (`testReturns405WithAllowHeaderWhenMethodDoesNotMatch`).
- Каждое требование раздела 4 имеет хотя бы один тест; соответствие — в матрице трассировки (подраздел 12.3).
- Тесты `ResponseEmitter` выполняются в отдельных процессах с `xdebug_get_headers()` либо через E2E; тесты, зависящие от `header()`, не запускаются в общем процессе.

### 8.3. Статический анализ и стиль

- **PHPStan** 2.x, уровень 10 (`max`); охват — `src/`, `app/`, `config/`, `public/`, `bootstrap.php`, `tests/`; каталог `resources/views/` исключён (переменные шаблонов динамические). Baseline и подавление ошибок в конфигурации запрещены. Типы `literal-string`, `class-string<T>`, формы массивов и шаблоны (`@template`) описываются в PHPDoc.
- **php-cs-fixer** 3.x: набор `@PER-CS3x0` плюс `declare_strict_types`; режим проверки (`--dry-run --diff`) в CI и режим исправления локально. По документации инструмента набор `@PER-CS3x0` реализует PER Coding Style 3.0, текущая редакция стандарта — 3.1; различия при внедрении не проверялись.
- **Запрет вызовов.** Правила подраздела T-ARCH-03 обеспечиваются архитектурным тестом; дополнительно допускается PHPStan-расширение запрета вызовов (подраздел 2.4, не проверено).
- **Локальные команды** — `composer qa` (стиль, анализ, тесты); конфигурации — раздел 9.

### 8.5. Проверка контрактов раздела 6

**При подготовке этого документа** листинги проверены: синтаксис — `php -l` на PHP 8.3.6; совместимость сигнатур с интерфейсами — загрузкой всех 17 классов из раздела 6 вместе с настоящими исходниками `psr/container` 2.0.2, `psr/log` 3.0.2, `psr/http-message` 2.0, `psr/http-factory` 1.1.0, `psr/http-server-handler` 1.0.2 и `psr/http-server-middleware` 1.0.2 (взяты с GitHub, так как Packagist из среды подготовки был недоступен). Загрузка подтвердила корректность `#[\Override]`, типизированных констант, `readonly`-классов и атрибута `#[\SensitiveParameter]` на PHP 8.3. Тела методов в листингах пусты, поэтому поведение листингами не проверялось.

**Требование к реализации.** `ContractTest` (T-ARCH-08) обязан через Reflection сравнить публичные сигнатуры реализованных классов с таблицей сигнатур, выгруженной из раздела 6 в тестовый файл; расхождение — ошибка сборки до внесения записи архитектурного решения.

### 8.6. Тестовая среда и данные

- Тесты запускаются на Linux; для E2E нужен свободный порт на `127.0.0.1` и расширение `pcntl` не требуется (используется `proc_open`).
- Данные для БД — SQLite в памяти; схема и данные создаются в `setUp`.
- Фабрики PSR-7 в тестах — `nyholm/psr7`; для изоляции от реализации допустимы собственные заглушки интерфейсов PSR.
- Время подменяется замыканием часов (`FileLogger`); случайность в ядре не используется.
- Файлы журнала и временные каталоги создаются в системном каталоге временных файлов и удаляются в `tearDown`.

### 8.7. Определение готовности (Definition of Done)

Задача считается выполненной, если: код соответствует разделам 4 и 6; для каждого затронутого требования есть тесты из подраздела 8.2; пройдены все шаги подраздела 8.4; публичные изменения отражены в PHPDoc и `CHANGELOG.md`; отступления от ТЗ оформлены записью архитектурного решения; в журнале и сообщениях нет секретов; код прошёл ревью второго разработчика.

### 9.2. `src/Middleware/SecurityHeaders.php`

| Параметр | Значение |
| --- | --- |
| Назначение | Добавляет заголовки безопасности к каждому ответу |
| Класс | `final readonly class SecurityHeaders implements MiddlewareInterface`, `@api` |
| Зависит от | `psr/http-server-middleware`, `psr/http-message` |
| Требования | FR-SEC-01..05, SEC-04, SEC-14 |
| Тесты | T-SEC-01..08 |

```php
<?php

declare(strict_types=1);

namespace Asguard01\PhpMvc\Middleware;

use Psr\Http\Message\ResponseInterface;
use Psr\Http\Message\ServerRequestInterface;
use Psr\Http\Server\MiddlewareInterface;
use Psr\Http\Server\RequestHandlerInterface;

/** @api */
final readonly class SecurityHeaders implements MiddlewareInterface
{
    /**
     * @param array<string, string> $headers Имя заголовка => значение; пустое значение отключает заголовок
     *
     * @throws \InvalidArgumentException если имя или значение заголовка недопустимы
     */
    public function __construct(private array $headers) {}

    #[\Override]
    public function process(ServerRequestInterface $request, RequestHandlerInterface $handler): ResponseInterface {}
}
```

**Правила.**

- Имена и значения проверяются в конструкторе (имя — токен по RFC 9110; значение без CR, LF и NUL), поэтому во время обработки запроса звено не бросает исключений (FR-MW-06).
- Заголовок добавляется, только если в ответе его нет (сравнение имён без учёта регистра): обработчик может задать собственное значение.
- `Strict-Transport-Security` добавляется, только если `$request->getServerParams()['HTTPS']` задан и не равен `off` (без учёта регистра); схема URI и `X-Forwarded-Proto` не используются (FR-SEC-03).
- Звено вызывает следующий обработчик ровно один раз и не изменяет запрос.
- Значения по умолчанию задаёт `config/app.php` (подраздел 6.3.1; приложение B).

### 9.3. `public/worker.php`

| Параметр | Значение |
| --- | --- |
| Назначение | Точка входа воркера FrankenPHP: старт приложения один раз, обработка запросов в цикле (P3) |
| Зависит от | `bootstrap.php`, `ResponseEmitter`, `nyholm/psr7*`, функция `frankenphp_handle_request()` |
| Требования | FR-ENTRY-07, WK-1..WK-8, Ц-4 |
| Тесты | T-WK-01..07, сборка образа (8.4, шаг 9) |

```php
<?php

declare(strict_types=1);

use Asguard01\PhpMvc\Http\ResponseEmitter;
use Nyholm\Psr7\Factory\Psr17Factory;
use Nyholm\Psr7Server\ServerRequestCreator;

// Обрыв соединения клиентом не должен завершать скрипт воркера
ignore_user_abort(true);

$kernel = require dirname(__DIR__) . '/bootstrap.php';
$factory = new Psr17Factory();
$creator = new ServerRequestCreator($factory, $factory, $factory, $factory);
$emitter = new ResponseEmitter();

$handler = static function () use ($kernel, $creator, $emitter): void {
    $level = ob_get_level();

    try {
        $emitter->emit($kernel->handle($creator->fromGlobals()));
    } catch (Throwable $e) {
        error_log(sprintf('Fatal %s: %s in %s:%d', $e::class, $e->getMessage(), $e->getFile(), $e->getLine()));

        if (!headers_sent()) {
            http_response_code(500);
            header('Content-Type: text/plain; charset=UTF-8');
            header('Cache-Control: no-store');
            header('X-Content-Type-Options: nosniff');
            echo 'Internal Server Error';
        }
    } finally {
        if (ob_get_level() > $level) {
            error_log('Warning: output buffers were left open after the request.');

            while (ob_get_level() > $level) {
                ob_end_clean();
            }
        }
    }
};

$maxRequests = (int) ($_SERVER['MAX_REQUESTS'] ?? getenv('MAX_REQUESTS') ?: 0);

for ($count = 0; $maxRequests === 0 || $count < $maxRequests; ++$count) {
    $keepRunning = frankenphp_handle_request($handler);

    // Сборка мусора вне обработки запроса
    gc_collect_cycles();

    if (!$keepRunning) {
        break;
    }
}
```

**Правила.** Скрипт построен по образцу из [документации FrankenPHP](https://frankenphp.dev/docs/worker/): обработчик определён вне цикла, суперглобальные переменные и `php://input` сбрасываются перед каждым запросом, исключения ловятся внутри обработчика. `0` в `MAX_REQUESTS` означает «без ограничения». Прямой доступ к файлу по URL закрыт настройками сервера (подраздел 10.2). Функции `frankenphp_handle_request()` в PHPStan соответствует заглушка `stubs/frankenphp.stub` (9.4).

### 10.2. Веб-сервер

**Обязательные свойства конфигурации любого сервера.**

- Корень — каталог `public/`; в корне исполняется только `index.php` (и `worker.php` не по URL); остальные `*.php` отвечают 404.
- Любой запрос к несуществующему файлу направляется в `index.php`; строка запроса сохраняется.
- Доступ к скрытым файлам (`/.env`, `/.git`) закрыт; исключение — `/.well-known/` для выпуска сертификатов.
- Каталоги не индексируются; баннеры версий отключены.
- TLS обязателен; для PHP передаётся `HTTPS=on` (иначе HSTS не включится, FR-SEC-03); входящий `X-Forwarded-Proto` прокси перезаписывает или удаляет.
- Лимит размера тела запроса задан явно (`client_max_body_size` для nginx; согласован с `post_max_size`).

**Пример для nginx + PHP-FPM** (пример; проверить командой `nginx -t` при внедрении, в этом документе не проверялся):

```nginx
server {
    listen 443 ssl;
    server_name example.com;
    root /var/www/app/current/public;
    index index.php;

    client_max_body_size 8m;

    # Скрытые файлы закрыты, кроме /.well-known/
    location ~ /\.(?!well-known) {
        return 404;
    }

    location / {
        try_files $uri /index.php$is_args$args;
    }

    location = /index.php {
        include fastcgi_params;
        fastcgi_pass unix:/run/php/php-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        fastcgi_param DOCUMENT_ROOT $realpath_root;
        fastcgi_param HTTPS on;
        fastcgi_hide_header X-Powered-By;
    }

    # Остальные PHP-файлы не исполняются
    location ~ \.php$ {
        return 404;
    }
}
```

`$realpath_root` нужен, чтобы при переключении ссылки `current` на новый релиз OPcache не обслуживал старые файлы. **Apache:** `AllowOverride` разрешает `public/.htaccess` (подраздел 6.2.2) либо правила переносятся в конфигурацию виртуального хоста. **FrankenPHP:** образ или бинарник в режиме воркера с `FRANKENPHP_CONFIG="worker ./public/worker.php"` (пример `deploy/Dockerfile`: базовый образ FrankenPHP с PHP не ниже 8.3, копирование приложения в `/app`, установка зависимостей `composer install --no-dev --classmap-authoritative`, переменная `FRANKENPHP_CONFIG`); ограничение числа запросов — `MAX_REQUESTS` (подраздел 5.3) и/или средства самого FrankenPHP (сверить с документацией на дату внедрения).

### 10.3. Сборка и выпуск

```text
1. Получить исходный код нужного тега.
2. composer install --no-dev --classmap-authoritative       # без dev-пакетов; автозагрузка из карты классов
3. Убедиться, что в артефакте нет .env, tests/, docs/, .git/
4. Передать артефакт в среду: каталог релиза /var/www/app/releases/<идентификатор>
5. Подключить секреты (переменные окружения); проверить, что APP_ENV=prod
6. Переключить ссылку current на новый релиз (атомарно)
7. Перезагрузить PHP-FPM (или перезапустить воркеры FrankenPHP) для сброса OPcache
8. Проверить запрос GET / и журнал; при ошибке — откат: вернуть ссылку current и повторить шаг 7
```

Ядро не пишет в каталоги релиза. Миграции базы данных вне ядра: при их использовании они выполняются отдельным шагом до шага 6 и обратно совместимы с предыдущим релизом, чтобы откат был безопасен.

### 10.4. Права и каталоги

- Код и `vendor/` доступны пользователю PHP только для чтения.
- `storage/logs/` доступен на запись только если журнал пишется в файл; в production по умолчанию журнал идёт в `php://stderr`.
- В `public/` нет файлов, которые нельзя отдавать клиенту; запись в `public/` пользователю PHP запрещена.
- Файл журнала создаётся с правами, не дающими чтения посторонним пользователям (`umask` процесса 0027 или строже).
- Каталог журнала создаёт процесс развёртывания: `FileLogger` его не создаёт (подраздел 6.4.16).

### 10.5. PHP и OPcache

Рекомендуемые настройки — приложение E. Для production `opcache.validate_timestamps=0` и перезагрузка PHP при каждом выпуске. Предзагрузка (`opcache.preload`) не требуется. Расширения отладки (`xdebug`) не устанавливаются. Запуск скриптов, меняющих состояние OPcache, через HTTP запрещён.

### 10.6. Журналы и оповещения

**Куда пишется.** Контейнеры и платформы: `php://stderr` или `php://stdout`, сбор выполняет платформа ([Twelve-Factor, «Logs»](https://12factor.net/logs)). Классический сервер с файлом: `LOG_FILE=/var/log/app/app.log`, ротация внешней утилитой; поскольку `FileLogger` открывает файл при каждой записи, ротация переименованием не требует перезапуска приложения. Журнал ошибок самого PHP (`error_log`) направляется туда же, где собираются остальные журналы.

**Примеры разбора (`jq`).**

```text
jq -c 'select(.level == "error")' app.log
jq -r 'select(.context.status == 500) | [.time, .context.path, .context.exception.class] | @tsv' app.log
jq -c 'select(.level == "warning" and (.message | test("buffers")))' app.log
```

**Что отслеживать.** Всплеск записей `error`; появление записей `Fatal` и `Unhandled` (last resort); рост числа 404 и 405 (сканирование); записи `warning` об отброшенных буферах; предупреждения об устаревании после обновления PHP; ошибки доступа к журналу (`error_log()` вместо журнала).

### 10.7. Мониторинг и проверка работоспособности

Ядро не содержит маршрутов состояния. Приложение добавляет маршрут `GET /health`: 200 без чувствительных данных, без обращения к БД (проверка живости); отдельный маршрут готовности может проверять БД. Метрики и распределённая трассировка подключаются middleware (раздел 11); процессные метрики воркера (память, число запросов) собирает платформа.

### 10.8. Резервное копирование и восстановление

Ядро не хранит состояния. Резервируются: база данных, секреты и конфигурация окружения (вне репозитория), при файловом журналировании — каталог журналов (по политике хранения). Восстановление: развернуть тег релиза, подключить секреты, восстановить базу. Порядок и сроки проверяются учебным восстановлением не реже одного раза в квартал (рекомендация).

### 10.9. Обновление PHP и зависимостей

- Патч-релизы PHP применяются по мере выхода; перед повышением минорной версии CI проходит на новой версии.
- Ветка PHP, получающая только исправления безопасности, остаётся в матрице CI до окончания поддержки (подраздел 2.1).
- `composer audit` запускается в CI и по расписанию; найденная уязвимость блокирует слияние и исправляется до выпуска.
- Обновления зависимостей выполняются по расписанию отдельными изменениями с прогоном полного набора тестов.
- Обнаруженные предупреждения об устаревании устраняются до выхода следующей мажорной версии PHP.

### 10.10. Соответствие принципам Twelve-Factor

| Принцип | Как выполняется |
| --- | --- |
| Кодовая база | Один репозиторий, один тег — один релиз |

## 11. Расширения после версии 1.0

Ядро расширяется без правки `src/`: через middleware, определения контейнера, конфигурацию и код в `app/`. Если расширению нужно изменить публичный API ядра, оно оформляется записью архитектурного решения и выходит в минорном выпуске 1.x (NFR-API-02).

### 11.1. Точки расширения

| Расширение | Точка подключения | Изменения в ядре | Замечания |
| --- | --- | --- | --- |
| Сессии | Middleware после `ErrorHandler`; состояние — атрибут запроса | Нет | В воркере не использовать глобальное состояние `session_*`; собственное хранилище с идентификатором в cookie (SEC-11) |
| CSRF-защита | Middleware: токен для небезопасных методов (`POST`, `PUT`, `PATCH`, `DELETE`) | Нет | См. OWASP CSRF Prevention Cheat Sheet |
| Аутентификация и авторизация | Middleware, пользователь — атрибут запроса; проверки прав — в сервисах | Нет | SEC-11; проверка прав на объекты — всегда в приложении |
| CORS | Middleware до маршрутизации; предварительный запрос `OPTIONS` отвечает 204 | Нет | Явный `OPTIONS`-маршрут не нужен |
| Ограничение частоты | Middleware и внешнее хранилище (PSR-16) | Нет | Ответ 429 с `Retry-After` |
| Разбор JSON-тела | Middleware: `Content-Type: application/json` → `json_decode` с `JSON_THROW_ON_ERROR`, лимит глубины и размера; ошибка → `HttpException` 400; результат — `withParsedBody()` | Нет | Размер ограничивает и веб-сервер |
| Загрузка файлов | `getUploadedFiles()` (PSR-7) и сервис хранения | Нет | Проверка типа и размера — в приложении |
| Доверенные прокси и хосты | Middleware: по списку доверенных адресов заменяет схему и хост в URI | Нет | Ядро по-прежнему им не доверяет (SEC-14) |
| Идентификатор запроса, трассировка | Middleware: атрибут `request_id`, заголовки `traceparent` по W3C Trace Context | Нет | `ErrorHandler` уже читает атрибут (FR-ERR-12) |
| Метрики | Middleware: длительность, статус; экспортёр | Нет | Метки без значений параметров пути |
| События (PSR-14) | Сервис в контейнере | Нет | Ядро событий не публикует |
| Кэш (PSR-6, PSR-16), HTTP-клиент (PSR-18) | Сервисы в контейнере | Нет | Реализацию выбирает приложение |
| Группы маршрутов | Вспомогательная функция, добавляющая префикс к шаблонам | Нет | Маршруты остаются данными |
| Маршрутные middleware | Поле `middleware` в `Route`; конвейер на маршрут | Да: `Route`, `Dispatcher` (минорный выпуск) | До выхода — глобальные middleware с проверкой маршрута |
| Кэш маршрутов | Выгрузка скомпилированных таблиц `Router` в PHP-файл | Да: фабрика `Router::fromCompiled()` | Включение — при числе маршрутов, при котором компиляция заметна |
| Кэш конфигурации | Выгрузка массива `Config` в файл на этапе сборки | Нет | Файл вне веб-корня |
| Компиляция контейнера | Замена `Container` другой реализацией PSR-11 | Нет | `Kernel` и `Dispatcher` принимают любой `ContainerInterface` |
| Шаблонизаторы (Twig, Blade, Latte) | Адаптер за интерфейсом представления | Да: `ViewInterface` | До выхода — собственная обёртка в `app/` |
| Локализация | Сервис перевода; передача в шаблон данными | Нет (при необходимости — новый хелпер: минорный выпуск) | |
| Консольная точка входа, миграции | `bin/console`: собственный скрипт со сборкой контейнера из тех же конфигураций | Нет (общую часть `bootstrap.php` выделить в функцию — минорный выпуск) | Административные процессы по Twelve-Factor |
| Очереди, почта | Сервисы приложения, отдельные процессы-воркеры | Нет | |
| Послеответная обработка | Декоратор `ResponseEmitter`, вызывающий `fastcgi_finish_request()` в FPM | Нет | Для FrankenPHP — средства сервера |
| ORM, построитель запросов | Библиотека в `app/`, использующая собственное соединение | Нет | `Connection` остаётся тонкой обёрткой |
| WebSocket, GraphQL | Вне ядра | — | Отдельные точки входа |

### 11.2. Правила расширений

1. Расширение не изменяет файлы `src/`; все изменения — в `app/`, `config/` и пакетах Composer.
2. Middleware размещается в `config/middleware.php` после `ErrorHandler`, чтобы ошибки расширения обрабатывались и получали заголовки безопасности; исключения — звенья, которые обязаны выполниться до обработки ошибок, и они не бросают исключений в штатной работе (FR-MW-06).
3. Расширение не хранит состояние запроса в свойствах и `static`; его проверяют наборами T-WK (подраздел 8.2).
4. Конфигурация расширения — отдельный файл `config/<имя>.php` в формате FR-CFG-04.
5. Расширение имеет тесты, статический анализ и стиль на тех же уровнях, что ядро (NFR-MNT).
6. Новая зависимость — запись архитектурного решения (NFR-DEP-03).

## 14. Приложения

### Приложение A. Коды ответов ядра

| Код | Фраза | Источник | Условие | Тело | Заголовки | Журнал |
| --- | --- | --- | --- | --- | --- | --- |
| 200 | OK | Действие контроллера, `View::response()` | Штатный ответ | По действию | Заголовки безопасности | — |
| 204 | No Content | `Dispatcher` | `OPTIONS` без явного маршрута, путь существует | Нет | `Allow` | — |
| 400 | Bad Request | `Router` | Недопустимый путь (FR-ROUTE-07) | Фраза | — | `info` |
| 404 | Not Found | `Router`, `Dispatcher` | Нет маршрута; параметр пути не приводится к типу | Фраза | — | `info` |
| 405 | Method Not Allowed | `Router` | Путь известен, метод не подходит | Фраза | `Allow` | `info` |
| 500 | Internal Server Error | `ErrorHandler`, `Kernel`, `index.php`, `worker.php` | Необработанное исключение; ошибка сборки | Фраза (HTML или problem+json) либо `Internal Server Error` (`text/plain`) | `Cache-Control: no-store` | `error` |

Ядро не формирует: переадресации 3xx (завершающий слэш не нормализуется), 401 и 403 (расширения аутентификации), 413, 414 и 431 (веб-сервер), 429 (расширение ограничения частоты), 501–504 (платформа и прокси). Приложение вправе возвращать любой статус. Требование о заголовке `Allow` в ответе 405 — [RFC 9110](https://www.rfc-editor.org/rfc/rfc9110.html).

### Приложение B. Заголовки ответов

Значения по умолчанию заданы в `config/app.php` (подраздел 6.3.1); пустое значение отключает заголовок.

| Заголовок | Значение по умолчанию | Назначение | Замечания |
| --- | --- | --- | --- |
| `X-Content-Type-Options` | `nosniff` | Запрещает браузеру угадывать тип содержимого | — |
| `X-Frame-Options` | `DENY` | Защита от кликджекинга | Дублируется `frame-ancestors` в CSP |
| `Referrer-Policy` | `strict-origin-when-cross-origin` | Ограничивает передачу адреса в `Referer` | — |
| `Content-Security-Policy` | `default-src 'self'; base-uri 'self'; form-action 'self'; frame-ancestors 'none'; object-src 'none'` | Ограничивает источники ресурсов, блокирует встроенные скрипты и стили | Для пробного режима — имя `Content-Security-Policy-Report-Only` |
| `Permissions-Policy` | `camera=(), geolocation=(), microphone=()` | Отключает функции браузера | Список расширяется по потребностям приложения |
| `Cross-Origin-Opener-Policy` | `same-origin` | Изоляция контекста просмотра | Может мешать всплывающим окнам OAuth |
| `Cross-Origin-Resource-Policy` | `same-origin` | Запрещает загрузку ресурсов чужими источниками | Для общих ресурсов (CDN, внешние клиенты) смягчается |
| `Strict-Transport-Security` | `max-age=31536000; includeSubDomains` | Требует HTTPS | Только при `HTTPS` в параметрах сервера; `preload` не включён |

Не отправляются: `X-XSS-Protection` (устаревший механизм), `X-Powered-By` и `Server` (удаляются или скрываются сервером). Сверх списка приложение может добавить `Cross-Origin-Embedder-Policy`, `Clear-Site-Data` и `Cache-Control` для личных страниц. Значения — проектное решение по мотивам [OWASP HTTP Headers Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/HTTP_Headers_Cheat_Sheet.html); построчная сверка с актуальной редакцией справочника не выполнялась.

### Приложение E. `php.ini` для production

Рекомендации опираются на [OWASP PHP Configuration Cheat Sheet](https://cheatsheetseries.owasp.org/cheatsheets/PHP_Configuration_Cheat_Sheet.html) и общую практику; пределы ресурсов подбираются под приложение.

```ini
; --- Ошибки ---
error_reporting = E_ALL
display_errors = Off
display_startup_errors = Off
log_errors = On
; error_log: путь к файлу или syslog; в контейнерах не задаётся (вывод в stderr платформы)
zend.exception_ignore_args = On
zend.assertions = -1

; --- Раскрытие информации ---
expose_php = Off

; --- Ввод ---
variables_order = "GPCS"
request_order = "GP"
register_argc_argv = Off
default_charset = "UTF-8"
max_input_vars = 1000
max_input_time = 60
post_max_size = 8M
upload_max_filesize = 2M
max_file_uploads = 20

; --- Ресурсы ---
memory_limit = 128M
max_execution_time = 30

; --- Файлы и адреса ---
; allow_url_fopen = Off, если приложение не обращается к удалённым URL функциями файлов
allow_url_fopen = Off
allow_url_include = Off

; --- OPcache ---
opcache.enable = 1
opcache.validate_timestamps = 0
opcache.memory_consumption = 128
opcache.interned_strings_buffer = 16
opcache.max_accelerated_files = 10000

; --- Сессии (если подключено расширение сессий) ---
session.use_strict_mode = 1
session.use_only_cookies = 1
session.cookie_httponly = 1
session.cookie_secure = 1
session.cookie_samesite = "Lax"
```

Смысл настроек для ядра: `display_errors=Off` и `log_errors=On` — ошибки не показываются клиенту (SEC-05); `zend.exception_ignore_args=On` — в трассировках нет аргументов, значит нет паролей; `variables_order="GPCS"` — `$_ENV` пуст, ядро читает окружение через `getenv()` (FR-CFG-01); `expose_php=Off` — нет баннера версии; `opcache.validate_timestamps=0` — перезагрузка PHP при каждом выпуске (подраздел 10.5).
